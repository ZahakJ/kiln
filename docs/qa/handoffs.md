# Handoffs

Changes a work package made, or needs, outside the paths it owns (PLAN.md §4.7, §6). Append-only:
add entries at the end, never reorder or rewrite another work package's entries. The owning work
package reviews each entry and keeps, adapts or reverts the change in its own commits.

## WP-52 → WP-50 (repository scaffold)

- `package.json`: the `e2e` script is now `turbo run e2e --filter=@kiln/e2e --`, so arguments
  after `pnpm e2e` reach Playwright. Before, `pnpm e2e --grep bridge` (the acceptance form used by
  WP-52 and later work packages) failed with `turbo: ERROR unexpected argument '--grep' found`.
- `xtask/src/util.rs`: `repo_root()` resolves the repository at run time (the `CARGO_MANIFEST_DIR`
  that `cargo run` sets, then `cargo locate-project --workspace`), falling back to the
  compile-time path only when neither works. A cached `target/debug/xtask` built from another
  checkout (a temporary worktree sharing the target directory) used to write into that checkout.
  Agents should still not build from a temporary worktree into the shared `target/`.
- `xtask/src/main.rs`, `xtask/src/pending.rs`, `xtask/Cargo.toml`: registered the `protocol` and
  `wasm` subcommands (owned by WP-52 in `xtask/src/protocol.rs` and `xtask/src/wasm.rs`) and
  removed them from the pending list; `xtask` depends on `kiln-protocol` with the `schema`
  feature.
- `apps/desktop/src-tauri/Cargo.toml`, `apps/desktop/src-tauri/build.rs`: the shell depends on
  `kiln-protocol`, `kiln-session`, serde, postcard and the fs, dialog, opener, process and
  (desktop only) window-state plugins; `build.rs` declares the `kiln_*` IPC commands in the app
  manifest so Tauri generates one `allow-<command>` permission each (the generated files under
  `apps/desktop/src-tauri/permissions/autogenerated/`).
- `.github/workflows/ci.yml`: the rust job installs wasm-bindgen and binaryen, runs
  `cargo xtask wasm --release --ci` and uploads the built core; the web job downloads it for the
  bridge e2e tests. `pages.yml` and `release.yml` build the WebAssembly core before the web app.
- `biome.json`: `packages/protocol/src/generated` is excluded from lint and formatting, and
  `packages/protocol` is the only package allowed to import `@tauri-apps/*` (the thinness rule of
  PLAN.md §3.7 forbids it everywhere else).

## WP-56 → WP-57, WP-69, WP-60 (formula engine core)

- For WP-57 (function library): register families with `FunctionTable::register` (or implement
  `FunctionRegistry`) and pass the registry in `EngineOptions::registry`. An implementation is
  `fn(&mut [Arg], &mut dyn CallContext) -> EvalValue`; lazy positions (`FunctionSpec::lazy`, e.g.
  `ArgMask::ALL` for `IFS`/`LET`/`LAMBDA`, `ArgMask::bits(0).and_from(1)` for `CHOOSE`) arrive as
  `Arg::Lazy` (use `LazyArg::expr()`, `expr().as_local_name()` for LET/LAMBDA names, `ctx.evaluate(expr,
  scope)` with `Scope::bind`, `ctx.make_lambda`, `ctx.invoke`); lifted positions (`lift`) arrive as
  scalars and the engine broadcasts arrays. `crates/kiln-formula/tests/engine_support/mod.rs` has small
  test-only LET, LAMBDA, ISOMITTED, SEQUENCE, ROW, COLUMN, NOW, INDIRECT, OFFSET, COUNT, COUNTA, IFERROR
  and INDEX implementations that show the pattern (and that the library's versions should replace in
  those tests if it wants). `TEXT` should use `numfmt::NumberFormat` and map `FormatError::DateOutOfRange`
  to `#VALUE!`. `DocsHandle::Key` is there for the docs JSON. Circular references show 0 and are
  flagged (Excel's behaviour), not a `#CIRCULAR` error.
- For WP-69 (sheet model): implement `EngineHost` over the SparseStore (`cell_value`, `set_cell_value`,
  `used_bounds`, tables, `apply_structural_edit`, `row_visibility`); call `cell_changed` for edits made
  directly in the store and `tables_changed` when tables change. Spans in `ParseError` and the AST are
  byte offsets (convert to UTF-16 for the formula bar). Structural edits currently re-parse every
  formula (about 3 s per million formulas); shifting compiled formulas directly would make them instant.
- For WP-60 (`cargo xtask budgets`, docs/qa/perf.md): `cargo run --release -p kiln-formula --example
  recalc_bench` prints `full_recalc_ms` (B8) and `incremental_ms_p95` (B9). On 2026-10-16 on this
  machine: full recalculation of 1,000,008 formulas 867 ms on 4 threads (1,487 ms on 1), single-edit
  recalculation p95 0.12 ms in the 100,008-formula workbook and 0.12 ms in the million-formula one;
  building the million-formula workbook takes 3.1 s and 447 MB.
  The bench now exits with status 1 when either budget is missed, so `cargo xtask budgets` can rely
  on the exit code.
- For WP-72 (Formula Lab, `Query::FormulaTrace`): `Engine::explain(formula)` and
  `Engine::explain_at(formula, sheet, row, col)` evaluate a formula once, without storing it, and
  return an `ExplainStep` tree: each AST node's `kind`, `label` (function name, operator, `( )`,
  `(omitted)`), source `text` and `span` (byte offsets), `evaluated` (false for the untaken `IF`
  arm and everything under it), `count` (evaluations, e.g. 3 for a `MAP` lambda body over three
  items), `value` (references dereferenced), `reference` (`A1:A3`, `'Data 2'!A1`, `B:B`),
  `display` (`A1:A3 → {1;2;3}`, arrays previewed to 6×6 with `…`), and `description` (the
  registry's inline docs summary) or `docs_key` (for `DocsHandle::Key`). `format_value` and
  `format_scalar` are public for the same display text elsewhere. `=IF(SUM(A1:A3)>5,"x","y")` is
  covered by `tests/engine_explain.rs::formula_lab_example_shows_each_level`. Spans are bytes:
  convert to UTF-16 for the editor.
- For WP-57 (record in `docs/formula-deviations.md`, which WP-57 owns): circular references show 0
  and are flagged, as Excel does, instead of the `#CIRCULAR` error in the plan text. A cycle
  between defined names (`X=Y+1`, `Y=X+1`) evaluates to `#NAME?` (the name-nesting limit) rather
  than being reported as a circular reference. Number formats follow the numfmt oracle where it
  may differ from Excel, unverified for lack of an Excel oracle: format `0` shows `0` for -0.4
  (Excel may show `-0`; LibreOffice 24.2 also shows `0`), and `General` shows -0.0000001 and
  0.000012345 in decimal (LibreOffice agrees; Excel may use `-1E-07` and `1.2345E-05`). The core
  parser now rejects literal operands of `:` (`=1:1048577`, `=A1:5`) and `#` (`=1#`), as Excel does.
- For WP-69 (sheet model): `Engine::add_sheet` and `rename_sheet` accept any name, as the v1.0
  engine did; the sheet model must refuse empty names, names over 31 characters, names with
  `: \ / ? * [ ]`, names starting or ending with `'`, and `History`, before calling the engine.
  `insert_rows`/`insert_cols` also shift without checking for overflow (`insert_cols("S", 0,
  20000)` pushes every non-empty cell off the sheet); Excel refuses an insert that would push
  non-empty cells off the sheet, and only the sheet model knows the exact extent, so it must refuse
  before calling the engine.

## WP-59 → WP-50, WP-57, WP-60, WP-98 (parity tracker)

- `xtask/src/main.rs`, `xtask/src/pending.rs`, `xtask/Cargo.toml`, `Cargo.lock`: registered the
  `parity` subcommand (owned by WP-59 in `xtask/src/parity.rs`), removed it from the pending list,
  and added the workspace `regex` dependency to `xtask` (schema patterns, test-title matching).
- For WP-57 (function library): `cargo xtask parity` reads `conformance/functions-implemented.json`
  (`{"NAME": "implemented" | "planned"}`; a list of names is also accepted). When it lands, run
  `cargo xtask parity` and commit the regenerated `parity/functions.json` (computed `done` statuses),
  `PARITY.md` and `docs/parity-badge.json`, or `parity --check` fails CI. Every implemented name must
  be listed in `parity/functions.json` (523 Excel names; add a name there if Excel has one we missed).
  Flip the family rows `grid.formulas.functions.<family>` to `partial`/`done` only as far as the
  counts allow (`parity --check` enforces it), and the key-function rows
  (`grid.formulas.functions.lookup.XLOOKUP`…) with their `conformance:<csv>#<NAME>` ids.
- For WP-60 (`cargo xtask fidelity`, `docs/qa/fidelity.md`): `fidelity:<format>:<metric>>=<value>`
  verify ids read a summary table in `docs/qa/fidelity.md` with a `Format` column and one column per
  metric (`structural`, `text`, `visual`, `values`, `formulas`, `oracle_opens`,
  `byte_identical_untouched`), one row per format; values may be ratios, percentages or yes/no
  (contract in `parity/README.md`). The corpus manifest for the fidelity runner is
  `parity/corpus.json` (`files[].file` relative to `fixtures/`, `files[].checks`).
- For WP-98 (release) and every release after it: run `cargo xtask parity --snapshot vX.Y.Z` before
  tagging so PARITY.md lists the status flips since that release; add the badge
  `https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/ZahakJ/kiln/main/docs/parity-badge.json`
  to README.md (WP-59 does not own README.md).
- For WP-50 (`biome.json`): `parity/parity.json`, `parity/corpus.json` and `parity/functions.json`
  keep one row per line so parallel work packages flipping different rows never conflict;
  `biome format` at the root would expand them (and make `functions.json` stale). Please add
  `"!parity/parity.json"`, `"!parity/corpus.json"`, `"!parity/functions.json"` and `"!PARITY.md"`
  to `files.includes`. CI's `pnpm lint` runs per package, so nothing fails today.
