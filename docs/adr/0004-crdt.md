# ADR 0004: Collaboration and version history on Loro

- **Status:** accepted; evaluated in the implementation (2026-10-23)
- **Date:** 2026-10-15

## Decision

`kiln-collab` uses **Loro 1.16.2** (MIT) as the CRDT for live collaboration, offline merge, undo and
version history. **yrs 0.28.0** (MIT, the Rust port of Yjs) was evaluated and is the fallback.

## Why Loro

Both compile to WebAssembly and are maintained. Loro fits this architecture better:

1. A native rich-text CRDT with Peritext-style mark semantics; yrs has `XmlText` attributes but weaker
   behaviour for concurrent formatting.
2. A movable tree (slides, sections, notebooks, nested lists) and a movable list.
3. Built-in version control: shallow snapshots, `checkout(frontiers)` and `diff` between versions, which
   is the Version History feature.
4. An `UndoManager` scoped to the local peer.
5. A stable 1.x API since 2024.

yrs's advantage, wire compatibility with the JavaScript Yjs ecosystem, is worth nothing when both ends of
the wire are the Kiln core.

## How

- Write, Deck and Notes models map onto Loro containers: paragraph text to `LoroText` with marks, blocks
  to `LoroMovableList`, properties to `LoroMap`, slides and sections to `LoroTree`. Model transactions are
  applied as Loro changes; remote changes become model operations so layout invalidation stays
  incremental. The Grid's command log is serialisable for a later bridge.
- Undo through Loro's `UndoManager` (local edits only). The Loro update log goes into the autosave journal
  (`kiln-storage`) for crash recovery and offline merge.
- Transport: `kiln-collab-server` (`axum` 0.8 and `tokio` 1.53 WebSocket relay per room, `redb`
  persistence, shared-token authentication documented as not production-grade). Presence travels on the
  same socket; comments are model data.
- History: a version on every explicit save and every ten minutes of editing (at most 200 per document,
  thinned), listed, previewed read-only through the same Scene, named, restored as a new state, with a
  word-level diff for Write computed in Rust.

## As built

- **Mapping.** Each node with an id is a map (`k` kind, `id`) in a movable list; property sets are maps with
  one JSON value per field, so concurrent changes to different properties of one paragraph, run, cell or
  shape all survive; whole values (inline objects, text boxes, deck tables, masters and layouts, themes)
  are last-writer-wins. Run formatting is one text mark per `RunProps` field (`r.<field>`), each model mark
  one text mark (`m.<hash>`), each inline object a mark on its `U+FFFC`. Every mark is configured not to
  expand, and inserted text gets exactly the formatting the model gave it, so both sides always hold the
  same per-character formatting. Deck effects are a list (two people animating different shapes both keep
  theirs).
- **Local → CRDT.** A transaction's ops name what they touched (paragraphs, block lists, tables, sections,
  stories, parts); each is brought level with the model: text by one delete and one insert around the
  unchanged ends, formatting by marks where it differs, lists by moves and inserts.
- **CRDT → model.** Loro's events name the containers a merge changed. A text change is applied from the
  event's delta as `InsertInline`/`DeleteInline`/`SetRuns`/`AddMark`/`RemoveMark`/`SetObject` without
  reading the paragraph; other changes are read back and diffed into ops. Changes no op sequence
  expresses (a section break made elsewhere, masters and layouts) rebuild the model, flagged as such.
- **Ids.** Replicas allocate model ids in different lanes (`kiln_doc::IdLanes`, ids `≡ lane (mod 2^20)`). The
  relay gives each new replica the next lane of the room and never gives a lane out twice (a replica that
  reconnects names the lane it holds and keeps it), so concurrent inserts never collide; a room that has given
  out all 2^20 − 1 lanes refuses newcomers (`Refusal::Full`). Lane 0 holds the ids every replica derives alike
  (the empty paragraph of a list emptied by concurrent deletions, so two repairs make one paragraph).
- **Repair.** A merge that leaves a model invalid (a list emptied by concurrent deletes, a comment range whose
  comment was deleted, a reference to a deleted note or header, an animation of a deleted shape, a slide on
  a deleted layout) is repaired by the replica that merged it, as a change everyone receives.
- **Moved text.** A split writes the tail into the new paragraph and deletes it from the first; a join writes
  the second paragraph's text into the first. Each records, in the root map `moves` (one key per move), which
  characters it took, which characters they became and an operation of its change (changes that depend on it
  saw the move). Every replica that merges a record, or a change made at the same moment as one, repairs the
  result as a change of its own (`moves::Moves::repair`), which any number of replicas can do at once: a
  character two moves copied keeps the copy of the move that took fewer (the inner of two splits, one of two
  joins of a pair; a deletion of the other copy by someone who kept it is made in the copy kept), and when the
  inner split's paragraph came first the two swap their text; characters typed into the moved stretch at the
  same moment move after the moved characters, to the same place among them and with their formatting, each
  such move recorded so that two replicas moving the same characters leave one copy; characters deleted from
  the moved stretch at the same moment are deleted from the copy, wherever moves took it. A paragraph a join
  took that a concurrent list move put back goes again, and two joins in opposite directions that removed both
  paragraphs bring them back. Concurrent edits are found from the merge's operations (Loro's JSON export of the
  imported changes and their dependencies), so a replica that never edited, or one whose author has left,
  repairs as well. Proptests type unique characters, delete some and split and join on two and three replicas,
  one of them leaving for good, and check that every character typed and not deleted is there exactly once.
- **Undo** is Loro's `UndoManager`. A step that would remove a container holding characters it did not make
  (a paragraph split off that someone typed into, a text box someone typed in) is refused and the stack
  cleared, as Word does when it cannot undo.
- **Relay.** An update is stored before it is merged and relayed; one that cannot be stored is neither, and the
  sender is refused for now (`Refusal::Unavailable`) and sends it again on reconnecting. Client messages are at
  most 512 KB before and after the hello (a larger update comes in `Frame::Part`s, at most 64 MB), at most
  1,024 messages wait for a client before it is closed, and a room nobody is in leaves memory once compacted.
- **Deck slides** live in a tree, where the later of a move and a concurrent deletion wins; the replica that
  merges such a move deletes the slide again unless the mover had seen it deleted (Undo).
- **Version History** stores its versions in the document's CRDT (author, time, origin, name, frontiers), so
  everyone sees one list and it travels with the document. A version opens by forking the history at its
  frontiers; `VersionHistory::export` gives the shallow snapshot. Storing a shallow snapshot per version
  was measured and rejected: 1.4 MB for the 300-page document, so 200 versions would take 280 MB.
- **Web.** Linked into the per-app cores, Loro alone adds 757 KB gzipped to the Write core and the mapping
  another 290 KB, which takes Write (4,624 KB) and Deck (4,604 KB) over the 4,500 KB budget (B12).
  Collaboration is therefore its own module, `kiln-collab-wasm`, loaded only when a document is shared:
  1,714 KB gzipped (4,597 KB raw; budget 2,000 KB in `cargo xtask wasm`). The app core passes each applied
  transaction to it and applies the ops it returns. Native builds link `kiln-collab` directly.
- **Session.** One engine per shared document (`kiln_collab::Engine`: the replica, the sync client with its
  offline queue, presence and Version History) behind the calls of `kiln_protocol::collab::engine`. The session
  makes the same calls natively (`kiln_collab::Engines`) and on the web, where they cross to the collaboration
  module as postcard through `KilnSession.setCollab`. The WebSocket and the timers are host requests
  (`SocketOpen`, `SocketSend`, `SocketReceive`, `SocketClose`, `Timer`): the browser's `WebSocket` on the web,
  tokio-tungstenite on the session thread's host natively. While a document is shared its own undo stack is not
  used: Undo and Redo are the engine's (this peer's changes only).

## Measurements (release build, this machine)

| What | Result |
|---|---|
| B14: 1,000 remote operations (typing 70 %, deletes 15 %, bold 10 %, paragraph splits 5 %) merged one update at a time into model ops | 29.3 ms p95 with the repairs of moved text (budget 50 ms; 19.2 ms before them) |
| Loro import alone, 1,000 one-character updates | 6.2 ms |
| Update size | 121 bytes per operation on average |
| Share the 300-page document (3,712 paragraphs; 927 KB as postcard) | 335 ms; snapshot 1,944 KB, shallow snapshot 1,394 KB |
| Join it from the snapshot (decode and validate) | 152 ms |
| Share the 200-slide deck (610 KB as postcard) | 91 ms; snapshot 801 KB, shallow snapshot 568 KB; join 71 ms |
| Convergence | 128 random cases each (Write: two and three replicas, merge order, typed text on two and three replicas and with one leaving; Deck: two and three replicas against what was made and deleted, merge order); run once at 4,000 (Write), 10,000 (typed text) and 2,000 (Deck) |

## Consequences

- Inline objects, text boxes, deck tables, masters, layouts and themes merge as whole values.
- Formatting applied inside a stretch someone else moves at the same moment stays on the old characters.
- Text typed into a paragraph (or table, text box) someone else deletes as a whole at the same moment is
  deleted with it: block deletions are not moves.
- In a movable list a concurrent move keeps an element someone deleted: a paragraph or shape moved (or grouped)
  while deleted stays.
- Three or more splits of one paragraph at the same moment may leave the new paragraphs out of order (two are
  put in order).
- Edits not yet sent live in the open document only (the autosave journal holds them on disk); a room admits 2^20 − 1
  replicas over its life.
- `loro-internal` is pinned to 1.16.2 in `Cargo.lock`: `loro` 1.16.2 does not build against 1.17.

## Exit strategy

The `kiln-collab::Crdt` trait is deliberately small (`apply(update)`, `export_from(version)`,
`subscribe`, `undo`/`redo`, `snapshot`/`checkout`), so yrs can replace Loro if Loro stalls. The model
mappings are written against Loro's containers and would be rewritten with it.
