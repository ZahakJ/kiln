# Changelog

All notable changes to Kiln (called Officina until WP-50) are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The function library of Kiln Grid (`kiln_formula::functions`, WP-57): all 484 Excel worksheet functions of v1.0, ported to Rust with the same names, arities, volatility and lazy or lifted arguments (checked against a snapshot of the v1.0 registry) — Math & Trig, conditional aggregates, Statistical with every distribution, Logical with `LET`, `LAMBDA`, `MAP`, `REDUCE`, `SCAN`, `BYROW`, `BYCOL` and `MAKEARRAY`, Information, Text with `TEXT`, `TEXTSPLIT`, `TEXTBEFORE`, `TEXTAFTER` and regular expressions (now with look-around and back-references, and a step limit so no pattern can freeze recalculation), Date & Time with `NETWORKDAYS.INTL`, `WORKDAY.INTL`, `DATEDIF` and `YEARFRAC`, Lookup & Reference with `XLOOKUP`, `XMATCH`, `FILTER`, `SORT`, `SORTBY`, `UNIQUE`, `TAKE`, `DROP`, `HSTACK`, `VSTACK`, `TOCOL`, `TOROW`, `WRAPROWS`, `WRAPCOLS` and `EXPAND`, Financial, Engineering with `CONVERT`, complex numbers and Bessel functions, Database and `ENCODEURL`. Every function has its signature, argument descriptions and worked examples in `crates/kiln-formula/docs/*.json` (`functions::docs()`, `functions::doc(name)`, for autocompletion and the Formula Lab; `cargo run -p kiln-formula --example functions -- --doc XLOOKUP`), and all 866 examples evaluate as documented. The conformance suite runs in Rust (`cargo nextest run -p kiln-formula --test conformance`): 4,879 rows, including 279 new dynamic-array and LAMBDA rows, with 0 failures; another test calls every function at every arity with hostile arguments and requires an answer without a panic or a stall. `conformance/functions-implemented.json` feeds the parity tracker: 484 of the 505 functions in scope are done, and seven function families (Logical, Date & Time, Information, Engineering, Database, Compatibility, Web) are complete. In the WebAssembly build the library adds 577 KB compressed (gzip; 1.84 MB after `wasm-opt -Oz`) to the formula engine core, which the bridge links once the sheet model uses it; today's `kiln-bridge-wasm` artefact is unchanged.
- The command line `kiln-cli` (`docs/manual/cli.md`; installed as `kiln` by the Linux packages): `inspect` lists the parts, sizes, content types and relationships of any `.docx`, `.xlsx` or `.pptx` and pretty-prints a part with `--xml`; `repack` opens and saves a package without edits and reports `identical parts: N/N`; `render` writes a document's pages as PNG images (`--page`, `--dpi`, `--dark`) for every document kind the core can open; `control` is a JSON control channel over standard input and output for scripts and agents (new, open, execute any command, query, viewport, frame, render, save, subscribe, close); `eval` evaluates a formula; `fidelity` scores round trips. Exit status 0, 1 or 2 (usage).
- Measured quality, not claimed: `cargo xtask budgets` runs the benchmark harness `kiln-bench` (warm-up, p50/p95, peak memory, a calibration loop that scales the budgets to the machine) against `bench/budgets.toml` and writes `docs/qa/perf.md` with every §3.9 budget and its status, failing CI when one is missed — a million formulas recalculate in 0.7 s (B8) and an edit in a 100,000-formula workbook in 0.2 ms (B9); `cargo xtask fidelity` runs the round-trip fidelity scorer of `kiln-testing` (structure, text, values, formulas, LibreOffice opening the result, page images compared with LibreOffice's, untouched parts byte-identical) and writes `docs/qa/fidelity.md` — today the package-level baseline, 1,496 of 1,496 parts of 61 Office files byte-identical after a save. `kiln-testing` also brings fixture discovery, the LibreOffice oracle, image diffs and the formula conformance runner to Rust; `tools/make-fixtures.py --synthetic-large` generates the deterministic 300-page document, 1,000,000-cell workbook (200,000 formulas) and 200-slide presentation the budgets use; `@kiln/testing/playwright` gives the end-to-end tests helpers for typing and IME composition through the input proxy, screenshot names, accessibility scans and a layout scan.
- The parity tracker (`parity/README.md`, [PARITY.md](PARITY.md)): 802 rows covering every ribbon command of Kiln Write, Kiln Grid and Kiln Deck, every transition, animation, chart type and slide layout, Kiln Notes, the suite (files, print, storage, collaboration, themes, accessibility, languages, platforms, automation, AI, security) and 20 explicit out-of-scope rows (VBA, Access, OLE, IRM, 3-D models, Power Pivot…), each with its Office location, would-miss tier, priority, delivering work package and the tests that prove it; every Excel worksheet function (523 names from Microsoft's public list, 18 out of scope with reasons) in `parity/functions.json`; and every feature fixture with its fidelity thresholds in `parity/corpus.json`. `cargo xtask parity` validates all of it against a JSON Schema and the rules of PLAN.md §7 (critical rows are P0, done rows need passing automated tests, rows that exist to be better than Office can only be "better"…), computes the weighted score overall, per app and per tier, and regenerates PARITY.md and the shields.io badge endpoint `docs/parity-badge.json`; `--check` fails CI when they are stale; `--verify` runs the Playwright, nextest, Vitest, conformance and fidelity checks behind every done, better and partial row; `--snapshot <tag>` records the statuses at a release so PARITY.md lists the flips since. The seed score is 0.2 %: three suite rows are partial on the strength of the package layer (hostile files refused, untouched parts byte-identical, macros preserved).
- `docs/COMPETITORS.md`: the competitor dossier, re-scanned on 2026-10-16 with sources (ONLYOFFICE 10.0, LibreOffice 26.8, Univer 1.0, the Craft apps' v0.7.0 and their self-rated coverage, GenOffice's mail merge, Collabora's desktop app); the round-trip loop targets now require every chart type to survive a save.
- The formula engine core `kiln-formula` (`crates/kiln-formula/README.md`): a tokenizer and Pratt parser for every Excel reference form (A1, R1C1, sheet-qualified, 3-D, whole rows and columns, structured references, spill `#`, implicit intersection `@`, array constants) with byte spans and a canonical printer — every one of the 5,146 formulas in the conformance suite prints and re-parses to the same tree; reference rewriting for inserted and deleted rows and columns, copy, cut and paste, sheet renames and removal, A1↔R1C1 and the F4 toggle, preserving the user's spacing; Excel's value model (15-digit comparison, coercion of text such as `"1,234"`, `"(5)"` and `"Jan 15, 2024"`, date serials with the Lotus 1900 leap day and the 1904 system); a dependency graph in which `SUM(A:A)` is one interval-tree node, incremental recalculation by topological levels evaluated in parallel with deterministic results, Excel's handling of circular references (0 and a flag, or iterative calculation), dynamic arrays with spilling and `#SPILL!`, defined names, tables, 3-D references and structural edits; and the function registry the library plugs into. A million formulas recalculate in about 0.9 s on 4 threads and a single edit in a 100,000-formula workbook recalculates in about 0.14 ms (budgets B8 and B9).
- The Formula Lab's engine side: `Engine::explain` evaluates a formula once and returns every sub-expression with its source span, value (references shown as `A1:A3 → {1;2;3}`), whether it was evaluated at all (the untaken branch of `IF` is not) and how often (a `MAP` lambda body over three items: 3 times), with the function's one-line description. The parser now refuses literal operands of `:` and `#` (`=1:1048577`, `=A1:5`, `=1#`), as Excel does.
- Excel number formats (`kiln_formula::numfmt`): sections and conditions, colours, text, fills and skips, thousands and scaling, percent, scientific, fractions, dates, elapsed time, sub-seconds, AM/PM, locale and currency codes, and `General` with Excel's 11-character rule, checked against 2,035 cases generated from the `numfmt` oracle (`tools/gen-numfmt-cases.mjs`).
- The document surface (`docs/adr/0003-rendering.md`): documents are now laid out by the Rust core and painted on a canvas from a retained display list, the Scene (`kiln-scene`: rectangles, anti-aliased paths, glyph runs blitted from the core's glyph atlas, images, clips, transforms, gradients, shadows, squiggles, the caret and selection; tiles with content hashes and a hit-test index; frames that send only what changed and prefetch one screen ahead). The scratch document is set like Word's Normal style on Letter pages with soft page shadows (an ember glow in dark mode), and painting it in the browser (`@kiln/surface`) and in the core (`kiln-raster`, also behind `kiln-cli render --scratch file.txt --png out.png`) gives the same pixels (0.004 % apart on the reference page). Typing goes through an input proxy at the caret, so input methods, dead keys and the Android keyboard work (compositions are shown underlined and undone as one step); click, double-click (word with its trailing space, as in Word), triple-click, drag with autoscroll, Shift with the arrows, Home/End, Page Up/Down and Ctrl+A select; touch has tap, long press and teardrop handles; Ctrl+wheel, pinch and Ctrl+plus/minus zoom; scrolling a 500-paragraph document keeps 60 frames per second (2–4 ms of work per frame); a screen reader reads the visible pages through an off-screen mirror and follows the caret. A playground at `#/playground` shows it.
- The Office Open XML foundation `kiln-ooxml` (`crates/kiln-ooxml/README.md`): Office packages open with zip-bomb limits checked before anything is inflated (65,536 parts, 2 GB), password-protected and legacy binary files are recognised, damaged parts fail only when read, and saving copies every untouched part verbatim — a repack of all 58 feature fixtures is byte-identical part by part and a 22 MB workbook opens, inflates every part and repacks in under 50 ms. An order-preserving XML layer with no DTDs or entity expansion (billion-laughs and deeply nested files are refused cleanly), UTF-16 and legacy encodings, Office's namespace prefixes and Strict namespaces; DrawingML colours with every transform matched to Office's palette, fills, lines, effects, text properties, themes and all 187 preset shapes evaluated to vector paths; custom geometry (arc sweeps clamped to one turn as in Office, so a hostile file cannot make drawing run for ever), document properties and the passthrough of parts no reader models.
- The text engine `kiln-text` (`crates/kiln-text/README.md`): a font store with the bundled OFL document fonts (Liberation Sans/Serif/Mono 2.1.5, Carlito, Caladea; sources and checksums in `assets/fonts/SOURCES.md`), system fonts on desktop and Android, an Office substitution table (Calibri → Carlito, Cambria → Caladea, Arial → Liberation Sans, Times New Roman → Liberation Serif, Courier New → Liberation Mono, Aptos → the UI sans, symbol fonts reported) and script fallback chains; paragraph layout with Word's rules — shaping through parley/harfrust with a word shaping cache, bidi, tab stops with alignment and leaders, first-line and hanging indents, justify and distribute, automatic hyphenation (English and German) and soft hyphens, line spacing from the Windows metrics — with carets, hit testing, selection rectangles and word/sentence boundaries; and a glyph atlas (A8 and colour pages, quarter-pixel positioning, outlines for large text). Line breaks match LibreOffice on ten reference documents; 1,000 mixed paragraphs lay out in under 60 ms.
- The bridge between the interface and the Rust core (`docs/adr/0005-bridge.md`): one typed protocol (`kiln-protocol`) whose TypeScript types, command catalogue (`catalog.json`) and binary schema are generated by `cargo xtask protocol` and checked in CI; the session facade (`kiln-session`) that validates every command against its metadata (app, read-only, something to undo), keeps an undo history per document (one step per typed word, as in Word; undoing back to the saved state clears the unsaved-changes dot) and asks its host for files, dialogs, the clipboard and preferences; the WebAssembly build of the core (`cargo xtask wasm`, 131 KB compressed) running in a Web Worker; and the native bridge of the desktop and Android shell (IPC commands, an event channel, binary frames, permissions limited to exactly these commands and the file, dialog, link, process and window-state plugins).
- `@kiln/protocol`: the `KilnClient` interface with a Web Worker client and a Tauri client chosen at startup, browser and Tauri hosts (File System Access API with fallbacks, the browser's private file system, preferences, clipboard, web links only), and a binary frame decoder tested against vectors produced by Rust.
- A scratch document (plain paragraphs, real editing: whole emoji and accented letters, word-by-word caret movement, selections, paragraph splitting and joining, undo and redo, UTF-8 and UTF-16 text files) and two temporary pages that prove the loop: `#/frame` shows the core version from a round trip, `#/scratch` edits a scratch document through the core.
- Shared foundations in `kiln-common`: document and node ids, EMU/twip/point/pixel units with exact conversions, colours, geometry and error kinds.

### Changed

- Compared with the v1.0 library, functions with loops over an argument finish in bounded time on extreme input: `MULTINOMIAL(1E+308)` and `BESSELJ(1,1E+15)` no longer hang (as they did in v1.0), `DB` over a life of 10^15 periods uses a closed form, Bessel functions of large arguments use Hankel's expansion (more accurate as well as faster), and dates past 9999-12-31 in `YEARFRAC` and the security functions are `#NUM!`.
- Text layout no longer hangs or runs out of memory on documents with extreme indents, page widths or tab stops: paragraph geometry and letter spacing are clamped and tab leaders are bounded. Automatic hyphenation skips tokens longer than 96 characters, so a long pasted URL or base64 string no longer freezes layout.
- The `pnpm e2e` script passes its arguments to Playwright, so `pnpm e2e --grep <name>` runs one group of end-to-end tests.
- When an internal error interrupts an edit in the desktop app, that document becomes read-only and asks for a new name when saved, instead of carrying on with a possibly half-applied change; other documents are unaffected. A request for a file or dialog raised before the window finished loading is no longer lost, and reloading the window no longer duplicates its event stream.
- The suite is now called **Kiln**: Kiln Write (formerly Scriba), Kiln Grid (Tabula), Kiln Deck (Scena), Kiln Notes (Notula) and Kiln Home (Atrium). Package scope `@kiln/*`, application identifier `io.github.zahakj.kiln`, repository `ZahakJ/kiln`, website `zahakj.github.io/kiln`. The reasons and the new architecture are recorded in `docs/adr/0002-kiln-rust-core.md`.
- Kiln is being rebuilt on a native Rust core: a Cargo workspace with all 30 core crates (document, sheet and presentation models, layout, formulas, file formats, PDF, spell check, search, collaboration, storage, the session facade, the WebAssembly bridge, the command line, benchmarks and test support) and `cargo xtask` for repository tasks. The crates are scaffolds that build and are tested in CI; their engines follow.
- The desktop and Android shell is now Tauri 2 (`apps/desktop/src-tauri`), replacing Electron and Capacitor; it opens the web app in a window and can measure its own start-up time and memory (`kiln --startup-probe`).
- The v1.0 TypeScript engines (OOXML, formulas, document and sheet models, DOCX reader and writer, XLSX reader, fidelity scorer) moved to `reference/ts-core/` as a read-only oracle for the port; the formula conformance cases moved to `conformance/` and the test documents to `fixtures/`.
- Continuous integration now checks the Rust core (formatting, Clippy, tests, licences and advisories with cargo-deny, the WebAssembly build) and starts the desktop shell under a virtual display; the release workflow builds Tauri bundles for Linux, Windows and macOS, split Android APKs and a web archive, and checks installer sizes; a Pages workflow builds the landing page, manual and web app together.
- The landing page, README banner, social preview and app icons are neutral placeholders until the brand kit is imported.
- The interface no longer loads the Inter and JetBrains Mono web fonts; the brand kit's fonts replace them.

### Removed

- Placeholder packages for charts, collaboration, storage, printing, the ODF/PPTX/XLSX readers, the deck model, the Write, Grid and Deck editors, Notes, templates and i18n (recreated as thin views when their work packages start), and the Electron, Capacitor and Hocuspocus apps; TipTap, ProseMirror, Yjs, ECharts, fflate, fast-xml-parser, papaparse, numfmt, decimal.js, mathlive, nspell, pdf-lib, pdfjs-dist, dexie, comlink, immer and fontsource left the dependency catalog.

## v1.0 prototype (TypeScript, as Officina; not released)

### Added

- Monorepo scaffold: pnpm workspace with Turborepo, TypeScript, Biome, Vitest and Playwright; the four apps (web, desktop, Android, collaboration server) and the library packages; a licence gate for every shipped dependency.
- Repository hygiene: AGPL-3.0-or-later licence, README, contributing guide, security policy, Code of Conduct, issue and pull request templates, CODEOWNERS and Dependabot.
- Continuous integration (lint, typecheck, unit tests with coverage, licence check, end-to-end tests) and a release workflow that builds Linux, Windows, macOS and Android packages from a tag and attaches them with `SHA256SUMS.txt`.
- The Officina mark, the README banner in dark and light, the social preview image and the application icons, all rendered from SVG by `pnpm media:render`.
- Placeholder landing page and Markdown manual viewer on GitHub Pages.
- Reference documents: design overview, file-format fidelity notes, keyboard shortcuts and the release runbook.
- "Horizon" design tokens: light, dark and high-contrast themes (following the OS by default), per-app accent colours, spacing, radii, shadows, motion and type scale as CSS variables, a typed TypeScript object and a Tailwind 4 theme; the theme choice is remembered.
- Bundled fonts: Inter and JetBrains Mono for the interface, and the metric-compatible document fonts Liberation Sans/Serif/Mono, Carlito and Caladea so Office documents lay out like they do in Word.
- UI building blocks shared by every app: buttons (including Classic-ribbon large and split buttons), toggles, menus with submenus and shortcuts, tooltips with Office-style descriptions, dialogs, tabs, drop-down lists, an editable font/size box, unit-aware number fields, an Office-style colour picker with theme tints and recent colours, a zoom slider, a styles gallery, toasts, keyboard keycaps and scroll areas, all keyboard accessible.
- Officina Glyphs: 275 icons for Office commands (Format Painter, Merge & Center, Freeze Panes, Track Changes, slide layouts…), with an optional colourful style.
- The Office window: title bar with AutoSave, Save/Undo/Redo, rename-in-place and a Search box; the ribbon in Classic (three rows) or Simplified (one row) layout, chosen by window width, collapsible with Ctrl+F1, with contextual tabs, group dialog launchers and ScreenTips that show the shortcut and the Office name; the File menu (Backstage) in Office's order; a status bar with view buttons, a zoom slider and zoom presets, customisable from its right-click menu; task panes that dock left or right, resize and stack as tabs; the mini toolbar on selection; right-click menus.
- Every Office shortcut from the keyboard reference is mapped for Scriba, Tabula and Scena (including slide-show keys), with ⌘ on macOS; Key Tips (press Alt or F10, then the letters) reach every ribbon command.
- Command palette (Ctrl+Shift+P or Alt+Q): finds any command by its name, its Office name or everyday words ("merge and center", "freeze panes", "strikeout"), lists recent commands and shows shortcuts.
- File ▸ Options with General, Display, Proofing, Save, Language, Keyboard and Privacy pages; Keyboard lists every command and lets you reassign shortcuts the way Office's Customize Keyboard does. A Ctrl+/ cheat sheet lists the current app's shortcuts.
- Hooks for an optional writing assistant (summarise, rewrite, formula from a description, slides from an outline); none is configured by default and nothing is sent anywhere.
- Office Open XML core (`@officina/ooxml`): reads and writes the zip container of .docx, .xlsx and .pptx files, leaving every part it does not change byte-for-byte identical; refuses zip bombs and recognises password-protected files.
- Theme colours, fills, outlines, shadows, glow and reflection, and text formatting from DrawingML, resolved the way Office resolves them (theme tints and shades included).
- All 187 Office preset shapes (rectangles, arrows, callouts, flowchart symbols, stars, banners, action buttons…) drawn from their ECMA-376 definitions, with adjustment handles, text areas and connection points.
- Parts of a file Officina does not understand yet (macros, custom XML, embedded objects) are kept and written back on save instead of being dropped; document properties (title, author, custom fields) are read and written.
- Test corpus: 58 generated Word, Excel and PowerPoint feature files plus hand-made edge cases, a script that downloads 30 real-world files, and checks against LibreOffice, ExcelJS, mammoth and the Python Office libraries, with a round-trip fidelity scorer.
- Scriba document model (`@officina/doc-model`): documents keep Word's own structure and units (sections, paragraph and character formatting, tables with merged cells, headers and footers, footnotes, fields, bookmarks, equations, images and shapes, comments and tracked changes), so nothing is rounded or lost when a .docx is opened and saved.
- Styles behave like Word's: Normal, Heading 1–6, Title, Subtitle, Quote, List Paragraph, Caption, TOC 1–3, Header/Footer, Hyperlink, Strong, Emphasis and Table Grid with the Word 2016+ defaults (Calibri 11 pt, 1.08 lines, 8 pt after), and formatting is inherited in Word's order — table style, paragraph style, list level, character style, direct formatting — including Word's rule that Emphasis inside an italic paragraph shows upright.
- Lists number exactly as Word numbers them: multilevel and legal numbering, restart and continue, start values, bullets from Symbol and Wingdings fonts, Roman, letter, ordinal, word and East Asian formats.
- Field codes (PAGE, NUMPAGES, DATE/TIME with date pictures, TOC, REF, PAGEREF, HYPERLINK, SEQ) are understood, and unknown fields are kept unchanged.
- Office fonts are replaced by bundled look-alikes with identical spacing where one exists (Calibri → Carlito, Cambria → Caladea, Arial/Times New Roman/Courier New → Liberation), and fonts that may shift the layout (such as Aptos) are reported.
- Word count statistics as in Word (words, characters with and without spaces, paragraphs; East Asian characters counted one per word), and editing commands for styles, bold/italic toggling that respects styles, font size steps, case changes, lists and indents, tables (insert, rows, columns, merge, split), page and section breaks and page setup.
- Word document reader (`@officina/io-docx`): opens .docx, .docm, .dotx and .dotm files with their text, character and paragraph formatting, styles, lists, tables (merged cells, nested tables, widths in any unit), sections with first-page and odd/even headers and footers, footnotes and endnotes, comments with replies and resolved state, tracked changes (insertions, deletions, moves, formatting changes), fields with their last results (tables of contents become a contents block), hyperlinks, bookmarks, pictures, shapes and text boxes, equations, content controls, right-to-left text and document properties.
- Symbol-font characters (Wingdings, Symbol, Webdings) are shown as their Unicode equivalents and saved back as the original symbols.
- Anything the reader cannot edit yet (charts, SmartArt, embedded objects, legacy drawings, unknown parts) is kept for saving, and the Compatibility Checker gets a list of what will look different, with its location in the file.
- Formula engine (`@officina/formula`): Excel formula syntax including structured table references, 3-D and whole-column references, array constants, `@` and the `#` spill operator; formulas keep their own spacing when rows, columns or sheets change.
- Fast, incremental recalculation: only what changed is recalculated (a 100,000-cell chain in about 0.2 s), with circular reference detection and optional iterative calculation.
- Dynamic arrays that spill into neighbouring cells, with `#SPILL!` when something is in the way, plus LET, LAMBDA (including named and recursive lambdas), MAP, REDUCE, SCAN, BYROW, BYCOL and MAKEARRAY.
- A core set of 47 native functions (SUM, IF, XLOOKUP, FILTER, SORT, UNIQUE, SEQUENCE, TEXTJOIN, INDIRECT…) with Excel-compatible text-to-number, date and comparison rules, and a step-by-step evaluation tree for the upcoming Formula Lab.
- 484 Excel functions across financial, logical, text, date and time, lookup, math, statistical, engineering, information, database, web and compatibility families — including SUMIFS/COUNTIFS/AVERAGEIFS/MAXIFS/MINIFS with Excel criteria and wildcards, XLOOKUP/XMATCH match modes, SUBTOTAL and AGGREGATE that skip hidden and filtered rows, TEXT with Excel number formats, DATEDIF, NETWORKDAYS.INTL, the bond and depreciation functions, statistical distributions, Bessel and complex-number functions, CONVERT, TEXTSPLIT/TEXTBEFORE/TEXTAFTER, REGEX functions, CELL, INFO, ENCODEURL and HYPERLINK.
- Every function has built-in documentation (summary, syntax, arguments, worked examples) for formula autocomplete, the Insert Function dialog and the Formula Lab.
- A formula conformance suite of about 4,600 cases from Microsoft's documented examples and LibreOffice-recorded results; the places where Officina differs from Excel are listed in `docs/formula-deviations.md`.
- Tabula workbook model (`@officina/sheet-model`): sheets with Excel's full 1,048,576 × 16,384 grid in a compact sparse cell store (a million cells fill in about 0.15 s and iterate in under 20 ms), row heights and column widths in Excel's own units (the default column is 64 px), hidden rows and columns, outline levels, merged cells, defined names at workbook and sheet scope, tables, conditional formatting rules of every Office type, data validation, hyperlinks, notes and threaded comments, freeze panes and sheet views, print settings, AutoFilter state and chart/picture anchors.
- Cell formats are stored like Excel's styles.xml — fonts, fills, borders on every side in every style, alignment, protection and number formats — and identical formats are shared, so formatting a range twice never grows the file.
- Every spreadsheet edit is undoable: typing, formatting, inserting and deleting rows or columns (merges, names, conditional formats, validation, tables and every formula follow, with `#REF!` where a reference is deleted, and undo brings the original back exactly), cut and paste, paste special (values, formulas, formats, transpose, skip blanks), sort (several keys, custom lists, left to right), merge, sheet insert/delete/rename/move, freeze panes and more; edits group into one undo step and the history can be saved and replayed.
- Formulas in the workbook calculate as you type through the formula engine, only recalculating what changed, with spilling dynamic arrays, structured table references (renaming a table or a column header rewrites the formulas that use it, and converting a table to a range turns them into A1 references), defined names, manual calculation mode (F9, Shift+F9 for one sheet), the 1904 date system and a step-by-step explanation of any cell's formula.
- Numbers display exactly as Excel shows them: the General format's 11-character rule with automatic scientific notation, rounding half away from zero, dates and times (including elapsed `[h]:mm`), percentages, fractions, scientific, accounting layouts with the currency symbol pinned left, `[Red]`/`[Color n]` colours, conditional sections and localised separators and month names.
- Workbook snapshots as plain JSON (gzip-compressed for storage) for version history, crash journals and background workers.
