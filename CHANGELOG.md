# Changelog

All notable changes to Kiln (called Officina until WP-50) are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The brand kit (WP-51; `brand/BRAND.md`, `docs/design/README.md`). The design team's kit is imported verbatim into `brand/` by `tools/import-brand.sh` (idempotent), and everything user-facing now comes from it: `@kiln/tokens` is generated from `brand/tokens.json` (the kit's own `--kiln-*` names and `--app*` variables plus the semantic names the chrome uses, light, dark and a high-contrast theme assembled from kit colours, `data-app` for write = cobalt, grid = jade, deck = ember, notes = saffron and home = ember, a Tailwind 4 `@theme` block, a typed kit object, and a test that regenerates and diffs), with every text pair checked for WCAG AA. The interface fonts are Figtree and Fraunces (SIL OFL, `assets/fonts/brand/`). `@kiln/ui-kit`'s primitives take the kit's component styles (solid app buttons with a glaze foot, an ember button for suite actions, arch and segmented tabs, 28 px controls, raised gallery cards, app-tinted selection, app-coloured focus rings, Fraunces dialog titles) and gain the kit's glyph set (`AppGlyph`, `Spark`, `Flame`, `AppTile` with the drawing made for each size, `<Icon icon="brand:…">`); `pnpm --filter @kiln/ui-kit shots` renders every primitive in light and dark. The desktop, Android, Windows and macOS icons, the per-document icons, the favicon and PWA icons (with a web manifest), the README banner and the landing page (hero, fonts, app tiles, social preview) are the kit's. Mockups are in `docs/design/mockups/` with the work package that implements each; what the kit lacks is listed in `docs/design/kit-gaps.md`.
- Charts for Grid, Write and Deck (`kiln-charts`, WP-73; `crates/kiln-charts/README.md`, `docs/manual/charts.md`, `docs/FORMATS.md`). Thirteen chart types — clustered, stacked and 100 % column and bar, line (with markers, smooth), area (stacked), pie, doughnut, scatter, bubble, radar, combo with a secondary axis, treemap and sunburst — are read from and written to Office chart parts (`c:chartSpace` and Excel 2016's `cx:chartSpace`) without losing anything: every chart of the test files round-trips with the same structure, elements Kiln does not model stay in place and unedited formatting is written back as it was. Charts are laid out like Excel (automatic bounds and round tick steps, slanted or thinned category labels when they crowd, legends that wrap into rows, data labels that step aside) and drawn into the Scene with labels shaped by kiln-text; on screen, charts of documents with Office's default theme use Kiln's palette, tuned for light and dark. Editing (`SuiteCommand::Chart*`): insert from a range with Recommended Charts, change type, switch row/column, select data, add or remove elements, Office's eleven quick layouts, styles and colours, the title, series and axis formatting, move chart. `@kiln/ui-kit` has the chart chrome the app ribbons use: type galleries, Change Chart Type, Recommended Charts, Select Data, Add Chart Element, Quick Layout, Change Colors, Move Chart, the Format Chart pane and the Chart Design and Format contextual tabs.
- Chart fixes and additions (WP-73): Insert ▸ Chart in Write and Deck makes a chart of any type with Office's sample data kept in the chart; Change Chart Type no longer writes an element twice in a series (a radar chart with `c:smooth` changed to a smooth line wrote it twice, which Excel may call unreadable, and reopened as a line with markers) and checks every test chart against every type; choosing a combo for a one-series chart is refused with a message instead of silently making a column chart; choosing Pie pulls exploded slices in. The Chart Design tab lays out each control in its own column (they overlapped), the Format tab gains Shape Outline and a submenu per series with the current colour checked, and the Format Chart pane shows each axis's real bounds and units (marked Auto or with Reset), labels its Fill and Line rows and marks the colour in use. The chrome reads all of this from the core's new `ChartState` (`kiln_charts::state::chart_state`), including the chart's own Change Colors sets. Data labels inside bar and column segments are left off segments too short to hold them (they spilled over slivers of stacked charts) and are kept within the segment otherwise.
- Kiln Grid opens and saves Excel workbooks, CSV, TSV and JSON (`kiln-io-xlsx` and `kiln-io-csv`, WP-70; `crates/kiln-io-xlsx/README.md`, `crates/kiln-io-csv/README.md`, `docs/FORMATS.md`). `.xlsx`, `.xlsm`, `.xltx` and `.xltm` files are read with every cell value type, shared and rich-text strings, formulas (shared formulas, Ctrl+Shift+Enter arrays and dynamic arrays included, calculated on open), defined names, number formats, fonts, fills, borders, cell styles, merged cells, frozen panes and selection, column widths and row heights, conditional formatting with the Excel 2010 data bars and icon sets, data validation, hyperlinks, page setup, headers and footers, page breaks, AutoFilter, tables, notes, threaded comments, drawing anchors, protection and both date systems. Saving starts from the opened file: what Kiln models is written from the model (reusing the file's own XML wherever nothing changed, so attributes Kiln does not know survive), and pivot tables, macros, external links, charts, pictures, slicers, custom XML and everything else keep their bytes. Every test workbook, including real files from Apache POI and a Strict-namespace file LibreOffice cannot open but Kiln's save of it can, reads back after a save with the same model, values and formulas, untouched parts byte-identical (`cargo xtask fidelity`: structural, values and formulas 1.000, LibreOffice opens all 31 outputs, page renders 0.999–1.000 alike); values and formats agree with an independent reader (exceljs: all values and formulas, formats ≥ 0.99), and the 354 formula results of the feature workbooks agree with LibreOffice's recalculation except 14 cells where LibreOffice 24.2 lacks the function or differs from Excel by design (listed in the test). Edited workbooks — new values, formulas and dynamic arrays, formats, inserted rows, added, renamed and removed sheets, notes, links, conditional formats, validation, merges, sizes, names — save and reopen exactly, and LibreOffice opens them. A 1,000,000-cell workbook with 200,000 formulas opens ready to paint in about 0.7–0.9 s and is fully calculated after another 0.8 s (budget B7: 1.2 s / 2.5 s; `cargo xtask budgets --only B7`, `examples/open_bench.rs`); `sheetData` is read by a small strict streaming tokenizer, never built into a tree, and damaged or hostile files give errors or warnings, never a crash. CSV and TSV files open with the encoding (UTF-8 with or without BOM, UTF-16, Windows-1252) and delimiter detected and every field recognised as Excel's cell entry does (numbers, percentages, currency, dates, times, logicals, errors); saving writes the active sheet as Excel does (cells as displayed, Excel's quoting, CRLF), and `kiln-cli convert book.xlsx book.csv` gives the values LibreOffice's own conversion gives. A JSON array of objects opens as a table and a table saves as one. The session opens and saves Grid workbooks (`.xlsx`, `.xlsm`, `.xltx`, `.csv`, with the Compatibility Checker's list for CSV and macro-free saves; the grid surface is WP-71), `kiln-cli convert` converts between all of these formats, and the fidelity scorer measures workbook round trips (`kiln-testing`'s `.xlsx` adapter). The web core grows to 3.3 MB compressed (budget B12: 4.5 MB).
- The workbook model of Kiln Grid (`kiln-sheet`, WP-69; `crates/kiln-sheet/README.md`), ported from v1.0 and bound to the formula engine: workbooks of sheets over a sparse cell store (row chunks with columnar arrays, constant-time lookup, iteration by used range, the full 1,048,576 × 16,384 grid); cell formats deduplicated like Excel's `cellXfs` (fonts, fills, borders, number formats, alignment, protection), differential formats and named cell styles; merges, defined names, tables with structured references, totals rows, banded table styles (custom styles exactly, the built-in Light, Medium and Dark families from the theme) and automatic expansion when typing below a table or beside its header; every conditional-format rule type of Excel (cell value, formula, text, blanks, errors, dates, duplicates, top/bottom, above/below average, colour scales, data bars with negative values and axes, icon sets with custom icons) evaluated to per-cell formats, fills, bars and icons; data validation of every type with alerts, input messages, dropdown lists and Circle Invalid Data; hyperlinks, notes, threaded comments, row and column sizes, hiding and outline levels, freeze panes, split, zoom, right-to-left, page setup and sheet and workbook protection. Every edit is a command with an exact inverse — undo is exact even after a deletion turned references into `#REF!` — with an undo log of 1,000 steps, nestable transactions and a JSON history; a property test applies random sequences of 30 command kinds and checks that each step undoes and redoes exactly and that results always equal a workbook rebuilt from scratch. Also: Paste Special (values, formulas, formats, transpose, skip blanks, operations) and the clipboard to and from other applications as tab-separated text and HTML tables; AutoFill (linear and growth trends, days, weekdays, months, years, lists, numbered text); sort by several keys, custom lists, colours, case and locale (ICU collation); AutoFilter (values, dates, custom criteria with wildcards, top 10, dynamic dates, colours, icons); Remove Duplicates; Text to Columns; typed-entry recognition (`12%`, `$1,234.50`, `1/15/2024`); Excel's General format to 11 characters; workbooks saved to and restored from compact binary data. Formulas recalculate automatically after each edit or on F9, Shift+F9 and Ctrl+Alt+F9 in manual mode, with iterative calculation: through the model, a million formulas recalculate in about 1.0 s on four threads and an edit in a 100,000-formula workbook takes 0.2 ms (budgets B8 and B9; `examples/edit_bench.rs`).
- Kiln Grid: undoing a sheet rename now restores formulas that already named the new name (for example a `#REF!`
  reference to a removed sheet of that name), which the inverse's reverse rename used to rewrite. A full
  recalculation no longer reports a false circular reference (showing 0) for a dynamic array whose blocked spill
  area holds formulas that read each other; it shows `#SPILL!` as Excel does (WP-69 fix round).
- Kiln Write saves Word documents (`kiln-io-docx` writer, WP-65; `crates/kiln-io-docx/README.md`, `docs/FORMATS.md`): File ▸ Save and Save As write `.docx`, `.dotx` and `.docm`, and everything Kiln reads comes back exactly — paragraphs and runs with every setting, styles (keeping what Kiln does not edit, such as revision ids and Word 2010 text effects), lists, tables with merged cells and row and cell content controls, sections, headers and footers, footnotes and endnotes with their separators, threaded and resolved comments with their authors, tracked changes, fields with their results, bookmarks, hyperlinks, symbols, equations, pictures and shapes (written back exactly as Word wrote them unless edited, then only the edited properties change), text boxes, charts, SmartArt, embedded objects, macros (in `.docm`), custom XML and document properties. Parts no edit touched are copied byte for byte from the opened file: typing in the body rewrites the body and the document properties only, so styles, headers, notes, comments, media and everything Kiln does not model stay exactly as they were. Every test document, including real-world files from Apache POI, reads back after a save into the identical document — every paragraph, property and kept detail, node ids included — and an independent reader (mammoth) sees the same text; LibreOffice opens every saved file and renders the test documents as it renders the originals (visual score ≥ 0.92, 1.00 on the 19 feature documents; `cargo xtask fidelity`, `docs/qa/fidelity.md`); saving is deterministic, and saving a saved file again changes nothing. A 300-page document is read and written in about 120 ms. New documents are written with Word's parts (styles, settings, theme, font table). The Compatibility Checker (`Query::CompatReport`) lists what a save loses or changes — pictures without image data, macros when a `.docm` is saved as `.docx`, tracked moves saved as a deletion and an insertion, replies whose comment was deleted — followed by what was kept read-only on open. `kiln-cli convert in.docx out.docx` saves a file the way Kiln does and prints that list; the fidelity scorer now measures Word round trips (`kiln-testing`'s `.docx` adapter).
- Kiln Write lays out and paints Word documents (`kiln-doc-layout`, WP-63; `crates/kiln-doc-layout/README.md`): pages with their size, margins, orientation and columns; paragraphs exactly as styled, with tabs and leaders, justification, line spacing, borders and shading, list numbers and bullets, right-to-left text; Word's pagination rules — keep with next, keep lines together, widow and orphan control, page breaks before, page and column breaks, odd and even section breaks with Word's blank page; tables with autofit and fixed widths, merged cells, nested tables, cell shading and Word's border rules, rows that split across pages or move whole, header rows repeated on every page; pictures and shapes in the line or floating, with text wrapping square, tight and through (following the picture's outline), top and bottom, behind and in front, and text boxes; headers and footers for first, odd and even pages with live page numbers (in the section's number format), page counts, dates, file name and author; footnotes at the foot of the page, with the text making room for them, and endnotes after the text; comment balloon positions; print layout, web layout, read mode and draft. The 300-page test document paginates to 300 pages like LibreOffice, its first page is painted in about 70 ms and the whole document is paginated in about 150 ms (budget B3: 400 ms / 1.5 s; `cargo xtask budgets --only B3`); page counts of the feature documents equal LibreOffice's on 19 of 21 and are within one page on all (the two differences are where Word itself differs from LibreOffice). Edits re-flow only from the changed paragraph and stop as soon as the pages match the previous layout, so typing in a long document re-lays out a few pages. In the session, Write documents now paint (pages with the theme's page shadow, pictures uploaded once), take typing, deletion, selection by clicks and drags, caret movement by character, word, line (across page breaks), paragraph and page, and input-method composition, all undoable, report the page in the status bar and give screen readers the visible pages' headings, paragraphs, lists, tables and pictures with their positions; text in Word's automatic colour stays legible in the dark theme. `kiln-cli render report.docx --png out/page-%03d.png` writes one PNG per page. Benchmarks `write-open-300p` and `write-frame` measure it.
- Kiln Write opens Word documents (`kiln-io-docx`, WP-62; `crates/kiln-io-docx/README.md`, `docs/FORMATS.md`): `.docx`, `.dotx`, `.docm` and `.dotm` files are read into the Write document model with everything Word stores about paragraphs, characters, styles (including table styles and their header-row, banding and corner formats), lists, tables (merged cells, nested and floating tables), sections, headers and footers by page kind, footnotes and endnotes, threaded and resolved comments with their authors, tracked insertions, deletions, moves and formatting changes, fields with their last results (tables of contents as whole blocks, nested field codes shown as `{ … }`), hyperlinks, bookmarks, symbols, content controls, pictures inline and floating with every wrapping mode, shapes and text boxes with their text, equations and document properties. What Kiln does not edit — charts, SmartArt, ink, embedded objects, macros, custom XML, unknown formatting — is kept exactly as written for saving (the writer arrives with WP-65), and each such item is reported with its location for the Compatibility Checker. The body text of every test document is identical to that of an independent reader (mammoth); every Word file in the test corpus, including real-world files from Apache POI, opens without a crash; hostile files (deep nesting, corrupted bytes, broken fields, table grid counts far beyond Word's 63-column limit) are handled without a panic, even on the web build's small stack; a 300-page document is read in about 50 ms. `kiln-cli inspect --docx report.docx` prints the heading outline, counts and import diagnostics (`--json` too), and the control channel opens and queries Word documents; painting them follows with the Write layout engine (WP-63). The reader joins the WebAssembly core, which is now 1.67 MB compressed (budget B12: 4.5 MB).
- The document model of Kiln Write (`kiln-doc`, WP-61; `crates/kiln-doc/README.md`), ported from v1.0 and shaped like Word's own file format: sections with their page setup, columns, page numbering and headers and footers for first, odd and even pages (Link to Previous included); paragraphs and characters with every Word paragraph and font setting; tables with merged cells, borders, shading, banding and table styles; pictures and shapes inline or floating with text wrapping; footnotes and endnotes; threaded comments; fields (page numbers, dates in any of Word's date formats, tables of contents, cross-references, hyperlinks, sequence numbers — any other field is kept as written); bookmarks, hyperlinks, symbols and equations; tracked insertions, deletions, moves and formatting changes; content controls. Formatting resolves exactly as in Word — document defaults, table style (header row, banded rows, first column, corners), paragraph style, list level, character style (Emphasis inside an italic Quote is upright, as in Word) and direct formatting, theme fonts and theme colours with Word's tints and shades — and a new document has Word 2016–2021's defaults (Calibri 11 pt, 1.08 line spacing, 8 pt after, Heading 1 in Calibri Light 16 pt `2F5496`, and the 49 built-in styles a new Word document carries). Lists number like Word: continued and restarted lists, start-at values, legal numbering, outline numbering linked to heading styles, restart rules, and 33 number formats from Roman numerals, letters, ordinals and words to Hebrew, Arabic, Thai, Hindi and Chinese counting. Every edit is a transaction whose inverse restores the document exactly (checked on about a thousand random edit sequences, some 20,000 edits, in every test run), so undo and redo are exact; typing is undone one word at a time, as in Word. Word counts and character counts match Word's rules (each Chinese or Japanese character is a word, deleted text and dashes are not words). Documents save to and load from a compact binary form that is validated on load, so a damaged file is refused rather than half-read.

Every function has its signature, argument descriptions and worked examples in `crates/kiln-formula/docs/*.json` (`functions::docs()`, `functions::doc(name)`, for autocompletion and the Formula Lab; `cargo run -p kiln-formula --example functions -- --doc XLOOKUP`), and all 866 examples evaluate as documented. The conformance suite runs in Rust (`cargo nextest run -p kiln-formula --test conformance`): 4,879 rows, including 279 new dynamic-array and LAMBDA rows, with 0 failures; another test calls every function at every arity with hostile arguments and requires an answer without a panic or a stall. `conformance/functions-implemented.json` feeds the parity tracker: 484 of the 505 functions in scope are done, and seven function families (Logical, Date & Time, Information, Engineering, Database, Compatibility, Web) are complete. In the WebAssembly build the library adds 577 KB compressed (gzip; 1.84 MB after `wasm-opt -Oz`) to the formula engine core, which the bridge links once the sheet model uses it; today's `kiln-bridge-wasm` artefact is unchanged.
- The command line `kiln-cli` (`docs/manual/cli.md`; installed as `kiln` by the Linux packages): `inspect` lists the parts, sizes, content types and relationships of any `.docx`, `.xlsx` or `.pptx` and pretty-prints a part with `--xml`; `repack` opens and saves a package without edits and reports `identical parts: N/N`; `render` writes a document's pages as PNG images (`--page`, `--dpi`, `--dark`) for every document kind the core can open; `control` is a JSON control channel over standard input and output for scripts and agents (new, open, execute any command, query, viewport, frame, render, save, subscribe, close); `eval` evaluates a formula; `fidelity` scores round trips. Exit status 0, 1 or 2 (usage).
- Measured quality, not claimed: `cargo xtask budgets` runs the benchmark harness `kiln-bench` (warm-up, p50/p95, peak memory, a calibration loop that scales the budgets to the machine) against `bench/budgets.toml` and writes `docs/qa/perf.md` with every §3.9 budget and its status, failing CI when one is missed — a million formulas recalculate in 0.7 s (B8) and an edit in a 100,000-formula workbook in 0.2 ms (B9); `cargo xtask fidelity` runs the round-trip fidelity scorer of `kiln-testing` (structure, text, values, formulas, LibreOffice opening the result, page images compared with LibreOffice's, untouched parts byte-identical) and writes `docs/qa/fidelity.md` — today the package-level baseline, 1,435 of 1,435 parts of 61 Office files byte-identical after a save, with the same declared content types in all 61. `kiln-testing` also brings fixture discovery, the LibreOffice oracle, image diffs and the formula conformance runner to Rust; `tools/make-fixtures.py --synthetic-large` generates the deterministic 300-page document, 1,000,000-cell workbook (200,000 formulas) and 200-slide presentation the budgets use; `@kiln/testing/playwright` gives the end-to-end tests helpers for typing and IME composition through the input proxy, screenshot names, accessibility scans and a layout scan.
- The parity tracker (`parity/README.md`, [PARITY.md](PARITY.md)): 802 rows covering every ribbon command of Kiln Write, Kiln Grid and Kiln Deck, every transition, animation, chart type and slide layout, Kiln Notes, the suite (files, print, storage, collaboration, themes, accessibility, languages, platforms, automation, AI, security) and 20 explicit out-of-scope rows (VBA, Access, OLE, IRM, 3-D models, Power Pivot…), each with its Office location, would-miss tier, priority, delivering work package and the tests that prove it; every Excel worksheet function (523 names from Microsoft's public list, 18 out of scope with reasons) in `parity/functions.json`; and every feature fixture with its fidelity thresholds in `parity/corpus.json`. `cargo xtask parity` validates all of it against a JSON Schema and the rules of PLAN.md §7 (critical rows are P0, done rows need passing automated tests, rows that exist to be better than Office can only be "better"…), computes the weighted score overall, per app and per tier, and regenerates PARITY.md and the shields.io badge endpoint `docs/parity-badge.json`; `--check` fails CI when they are stale; `--verify` runs the Playwright, nextest, Vitest, conformance and fidelity checks behind every done, better and partial row; `--snapshot <tag>` records the statuses at a release so PARITY.md lists the flips since. - `docs/COMPETITORS.md`: the competitor dossier, re-scanned on 2026-10-16 with sources (ONLYOFFICE 10.0, LibreOffice 26.8, Univer 1.0, the Craft apps' v0.7.0 and their self-rated coverage, GenOffice's mail merge, Collabora's desktop app); the round-trip loop targets now require every chart type to survive a save.
- The formula engine core `kiln-formula` (`crates/kiln-formula/README.md`): a tokenizer and Pratt parser for every Excel reference form (A1, R1C1, sheet-qualified, 3-D, whole rows and columns, structured references, spill `#`, implicit intersection `@`, array constants) with byte spans and a canonical printer — every one of the 5,146 formulas in the conformance suite prints and re-parses to the same tree; reference rewriting for inserted and deleted rows and columns, copy, cut and paste, sheet renames and removal, A1↔R1C1 and the F4 toggle, preserving the user's spacing; Excel's value model (15-digit comparison, coercion of text such as `"1,234"`, `"(5)"` and `"Jan 15, 2024"`, date serials with the Lotus 1900 leap day and the 1904 system); a dependency graph in which `SUM(A:A)` is one interval-tree node, incremental recalculation by topological levels evaluated in parallel with deterministic results, Excel's handling of circular references (0 and a flag, or iterative calculation), dynamic arrays with spilling and `#SPILL!`, defined names, tables, 3-D references and structural edits; and the function registry the library plugs into. A million formulas recalculate in about 0.9 s on 4 threads and a single edit in a 100,000-formula workbook recalculates in about 0.14 ms (budgets B8 and B9).
- The Formula Lab's engine side: `Engine::explain` evaluates a formula once and returns every sub-expression with its source span, value (references shown as `A1:A3 → {1;2;3}`), whether it was evaluated at all (the untaken branch of `IF` is not) and how often (a `MAP` lambda body over three items: 3 times), with the function's one-line description. The parser now refuses literal operands of `:` and `#` (`=1:1048577`, `=A1:5`, `=1#`), as Excel does.
- Excel number formats (`kiln_formula::numfmt`): sections and conditions, colours, text, fills and skips, thousands and scaling, percent, scientific, fractions, dates, elapsed time, sub-seconds, AM/PM, locale and currency codes, and `General` with Excel's 11-character rule, checked against 2,035 cases generated from the `numfmt` oracle (`tools/gen-numfmt-cases.mjs`).
- The document surface (`docs/adr/0003-rendering.md`): documents are now laid out by the Rust core and painted on a canvas from a retained display list, the Scene (`kiln-scene`: rectangles, anti-aliased paths, glyph runs blitted from the core's glyph atlas, images, clips, transforms, gradients, shadows, squiggles, the caret and selection; tiles with content hashes and a hit-test index; frames that send only what changed and prefetch one screen ahead). The scratch document is set like Word's Normal style on Letter pages with soft page shadows (an ember glow in dark mode), and painting it in the browser (`@kiln/surface`) and in the core (`kiln-raster`, also behind `kiln-cli render --scratch file.txt --png out.png`) gives the same pixels (0.004 % apart on the reference page). Typing goes through an input proxy at the caret, so input methods, dead keys and the Android keyboard work (compositions are shown underlined and undone as one step); click, double-click (word with its trailing space, as in Word), triple-click, drag with autoscroll, Shift with the arrows, Home/End, Page Up/Down and Ctrl+A select; touch has tap, long press and teardrop handles; Ctrl+wheel, pinch and Ctrl+plus/minus zoom; scrolling a 500-paragraph document keeps 60 frames per second (2–4 ms of work per frame); a screen reader reads the visible pages through an off-screen mirror and follows the caret. A playground at `#/playground` shows it.
- The Office Open XML foundation `kiln-ooxml` (`crates/kiln-ooxml/README.md`): Office packages open with zip-bomb limits checked before anything is inflated (65,536 parts, 2 GB), password-protected and legacy binary files are recognised, damaged parts fail only when read, and saving copies every untouched part verbatim — a repack of all 58 feature fixtures is byte-identical part by part and a 22 MB workbook opens, inflates every part and repacks in under 50 ms. An order-preserving XML layer with no DTDs or entity expansion (billion-laughs and deeply nested files are refused cleanly), UTF-16 and legacy encodings, Office's namespace prefixes and Strict namespaces; DrawingML colours with every transform matched to Office's palette, fills, lines, effects, text properties, themes and all 187 preset shapes evaluated to vector paths; custom geometry (arc sweeps clamped to one turn as in Office, so a hostile file cannot make drawing run for ever), document properties and the passthrough of parts no reader models.
- The text engine `kiln-text` (`crates/kiln-text/README.md`): a font store with the bundled OFL document fonts (Liberation Sans/Serif/Mono 2.1.5, Carlito, Caladea; sources and checksums in `assets/fonts/SOURCES.md`), system fonts on desktop and Android, an Office substitution table (Calibri → Carlito, Cambria → Caladea, Arial → Liberation Sans, Times New Roman → Liberation Serif, Courier New → Liberation Mono, Aptos → the UI sans, symbol fonts reported) and script fallback chains; paragraph layout with Word's rules — shaping through parley/harfrust with a word shaping cache, bidi, tab stops with alignment and leaders, first-line and hanging indents, justify and distribute, automatic hyphenation (English and German) and soft hyphens, line spacing from the Windows metrics — with carets, hit testing, selection rectangles and word/sentence boundaries; and a glyph atlas (A8 and colour pages, quarter-pixel positioning, outlines for large text). Line breaks match LibreOffice on ten reference documents; 1,000 mixed paragraphs lay out in under 60 ms.
- The bridge between the interface and the Rust core (`docs/adr/0005-bridge.md`): one typed protocol (`kiln-protocol`) whose TypeScript types, command catalogue (`catalog.json`) and binary schema are generated by `cargo xtask protocol` and checked in CI; the session facade (`kiln-session`) that validates every command against its metadata (app, read-only, something to undo), keeps an undo history per document (one step per typed word, as in Word; undoing back to the saved state clears the unsaved-changes dot) and asks its host for files, dialogs, the clipboard and preferences; the WebAssembly build of the core (`cargo xtask wasm`, 131 KB compressed) running in a Web Worker; and the native bridge of the desktop and Android shell (IPC commands, an event channel, binary frames, permissions limited to exactly these commands and the file, dialog, link, process and window-state plugins).
- `@kiln/protocol`: the `KilnClient` interface with a Web Worker client and a Tauri client chosen at startup, browser and Tauri hosts (File System Access API with fallbacks, the browser's private file system, preferences, clipboard, web links only), and a binary frame decoder tested against vectors produced by Rust.
- A scratch document (plain paragraphs, real editing: whole emoji and accented letters, word-by-word caret movement, selections, paragraph splitting and joining, undo and redo, UTF-8 and UTF-16 text files) and two temporary pages that prove the loop: `#/frame` shows the core version from a round trip, `#/scratch` edits a scratch document through the core.
- Shared foundations in `kiln-common`: document and node ids, EMU/twip/point/pixel units with exact conversions, colours, geometry and error kinds.

### Changed

- The provisional "Horizon" look is gone (WP-51): tokens, primitives, icons, banners and the landing page follow the brand kit, and the old Inter/JetBrains Mono UI fonts are no longer referenced. `tools/render-media.mjs` now only renders the sizes the kit ships as SVG and builds the macOS `.icns` and Windows `.ico` reproducibly from the kit's drawings.
- Saving a workbook whose formula is nested tens of thousands of parentheses deep no longer exhausts memory and kills the app (WP-70): the step that adds Excel's `_xlfn.` and `_xlpm.` prefixes kept a copy of the open-parenthesis stack for every token, so a 200 KB formula needed tens of gigabytes; it now runs in linear time and memory (100,000 levels save in a fraction of a second). A part the XML writer cannot serialise is reported as an error instead of being saved empty. CSV and JSON imports follow Excel's limits with one warning each — cells cut to 32,767 characters, rows wider than 16,384 columns and JSON objects with more than 16,384 keys cut to fit (such JSON used to fail outright) — the scalars of a mixed JSON array are kept in a `value` column instead of being dropped, and JSON export writes whole numbers as integers. The 14 formula results LibreOffice cannot vouch for are checked against hand-computed values, and the three workbooks exceljs cannot read against openpyxl.
- Word documents with tables nested thousands of levels deep (Apache POI's `deep-table-cell.docx`, 15,005 elements) now open instead of being refused, and save without losing a word: the XML layer can keep content past its 2,000-element tree limit as verbatim markup (`ParseOptions::keep_too_deep_as_raw`, `XmlNode::Raw`), which the Word reader opts into; tables too deep to follow are kept whole (previously the innermost followed cell's content was dropped from a save); cells ending with a nested table get Word's end-of-cell paragraph on open, so a save and reopen gives the same document, and are saved ending with the table again while that paragraph is untouched, so LibreOffice shows the saved file as it shows the original (all 5,000 levels, visual score 1.00); whether a table is deep enough to keep whole is measured from its content, so content controls or links nested in the deepest followed cell are no longer dropped (WP-65 fix rounds, with WP-55/WP-62 code). `kiln-cli convert` counts relationships parts and the content types among the parts, so its summary never reports more written parts than the package has.
- Statistical distributions are accurate at any parameter size (WP-57). The incomplete gamma and beta functions behind them used to stop silently after 10,000 terms, so large shapes, degrees of freedom or trial counts gave wrong or impossible probabilities: `GAMMA.DIST(1E8,1E8,1,TRUE)` was 0.3414 (now 0.5000133), `BINOM.DIST(5E14,1E15,0.5,TRUE)` −81.38 (now 0.50000001), `T.DIST(0.5,1E15,TRUE)` 1.443 (now 0.6914625) and `GAMMA.INV(0.5,1E7,1)` 10000001 (now 9999999.67). Large shapes now use Temme's uniform asymptotic expansions, the beta continued fraction keeps its digits next to 1, the prefactors cancel their huge terms exactly, and a method that does not converge gives `#NUM!` instead of a partial sum; cumulative results stay within [0, 1]. `ERF`, `ERFC` and the normal distribution are now accurate to about 1e-15 (the `statrs` versions were off by up to 1e-10), and the large-parameter densities (`GAMMA.DIST`, `POISSON.DIST`, `BINOM.DIST`, `NEGBINOM.DIST`, `HYPGEOM.DIST`, `T.DIST`, `F.DIST`, `BETA.DIST` with `FALSE`) no longer lose digits to cancellation. 30 new conformance rows check large parameters against 50-digit references, and the fuzz test now requires every cumulative distribution function to return a probability. `MMULT` is about 7× faster (1000×1000 by 1000×1000 in 0.4 s) and `UNIQUE` of a million numbers about 14× faster (0.7 s); `functions --list | head` no longer panics on the closed pipe. Correction to the two WP-57 entries under Added: the suite now has 5,450 rows and 890 documented examples, and the library adds 587 KB gzip to the WebAssembly engine core (the first entry's 4,879 rows, 866 examples and 577 KB were the figures before the thirteen added functions).
- Inverse distributions are exact in the tails and at small shapes, and `BINOM.INV` always finishes (WP-57). `BINOM.INV` and `CRITBINOM` with 10¹⁶ or more trials never returned and froze recalculation (above 2⁵³ the bisection's `mid + 1` equals `mid`); they now answer in microseconds up to the largest double. The quantile search behind `GAMMA.INV`, `BETA.INV`, `T.INV`, `T.INV.2T`, `TINV`, `F.INV`, `F.INV.RT`, `CHISQ.INV`, `CHISQ.INV.RT` and `CONFIDENCE.T` bisected values for 300 steps, so it could not get below about 10⁻⁹¹ or converge on wide brackets: `GAMMA.INV(0.1,0.01,1)` was 2.45e-91 (now 5.66e-101), `T.INV(1E-18,1)` −1.34e154 (now −3.18e17) and `T.INV(1E-16,2)` −67108864 (now −70710678.1). It now bisects the bit patterns of doubles, reaching adjacent doubles in at most 64 steps at any scale, searches on the smaller tail (and the beta quantile on the side of ½ it lies on), and gives `#NUM!` when the quantile is beyond the largest double. Gamma, beta and F tails at a tiny fraction of the mean (`CHISQ.DIST(2.8E-6,30,TRUE)` was off in the 9th digit, `F.DIST(5.5E-17,1,1000,TRUE)` was 0 instead of 5.9e-9), `T.DIST` beyond ±10¹⁵⁴, `GAMMA.DIST(1E308,1E-300,1,TRUE)` and `NORM.S.INV` of a subnormal probability (both `#NUM!` before) are fixed too, and `BINOM.DIST.RANGE` and cumulative `HYPGEOM.DIST` no longer hang on whole numbers above 2⁵³ either. Cumulative `HYPGEOM.DIST` now sums from `s` away from the mode and stops at the first negligible term, so `HYPGEOM.DIST(1E7,2E7,2.5E7,5E7,TRUE)` takes 10 ms instead of giving `#NUM!`, samples just under the old limit drop from about 1.2 s to milliseconds, and results match 40-digit references to 1e-13. 47 new conformance rows check tail and small-shape quantiles against 60-digit references and the large-count cases, and two new fuzz tests require every inverse distribution to round-trip (the CDF of the quantile returns p) and `BINOM.INV` to finish at any trial count; the cumulative-distribution fuzz test now also fails on any call slower than 5 s.
- `cargo xtask budgets` no longer fails at random on a busy machine (WP-60): the benchmarks take enough timed runs for p95 to mean something (20 to 200 instead of 3 to 60); a benchmark over a limit is measured again, up to twice, after waiting for other processes to leave half of the CPUs idle, so a row fails only when every attempt misses it; and each attempt records the share of the CPUs other processes used, so when every attempt missed on a busy machine the row is reported as inconclusive rather than as a regression (a quiet machine, such as CI, gives the verdict). `docs/qa/perf.md` shows the attempts and the other processes' CPU share of each benchmark. `kiln-cli` exits 2 when run without a command, ends quietly when its output pipe is closed (`kiln-cli inspect … | head`) instead of panicking, and its control channel rejects arguments and viewport fields it does not know instead of ignoring them. `kiln-cli repack` and the fidelity baseline report `[Content_Types].xml` separately (compared by its declared content types) rather than counting it as a byte-identical part, and `sheet-1m.xlsx` now carries a `<dimension>` on each sheet, as Excel writes.
- Compared with the v1.0 library, functions with loops over an argument finish in bounded time on extreme input: `MULTINOMIAL(1E+308)` and `BESSELJ(1,1E+15)` no longer hang (as they did in v1.0), `DB` over a life of 10^15 periods uses a closed form, Bessel functions of large arguments use Hankel's expansion (more accurate as well as faster), and dates past 9999-12-31 in `YEARFRAC` and the security functions are `#NUM!`.
- Text layout no longer hangs or runs out of memory on documents with extreme indents, page widths or tab stops: paragraph geometry and letter spacing are clamped and tab leaders are bounded. Automatic hyphenation skips tokens longer than 96 characters, so a long pasted URL or base64 string no longer freezes layout.
- The `pnpm e2e` script passes its arguments to Playwright, so `pnpm e2e --grep <name>` runs one group of end-to-end tests.
- When an internal error interrupts an edit in the desktop app, that document becomes read-only and asks for a new name when saved, instead of carrying on with a possibly half-applied change; other documents are unaffected. A request for a file or dialog raised before the window finished loading is no longer lost, and reloading the window no longer duplicates its event stream.
- The suite is now called **Kiln**: Kiln Write (formerly Scriba), Kiln Grid (Tabula), Kiln Deck (Scena), Kiln Notes (Notula) and Kiln Home (Atrium). Package scope `@kiln/*`, application identifier `io.github.zahakj.kiln`, repository `ZahakJ/kiln`, website `zahakj.github.io/kiln`. The reasons and the new architecture are recorded in `docs/adr/0002-kiln-rust-core.md`.
- Kiln is being rebuilt on a native Rust core: a Cargo workspace with all 30 core crates (document, sheet and presentation models, layout, formulas, file formats, PDF, spell check, search, collaboration, storage, the session facade, the WebAssembly bridge, the command line, benchmarks and test support) and `cargo xtask` for repository tasks. The crates are scaffolds that build and are tested in CI; their engines follow.
- The desktop and Android shell is now Tauri 2 (`apps/desktop/src-tauri`), replacing Electron and Capacitor; it opens the web app in a window and can measure its own start-up time and memory (`kiln --startup-probe`).
- The v1.0 TypeScript engines (OOXML, formulas, document and sheet models, DOCX reader and writer, XLSX reader, fidelity scorer) moved to `reference/ts-core/` as a read-only oracle for the port; the formula conformance cases moved to `conformance/` and the test documents to `fixtures/`.
- Continuous integration now checks the Rust core (formatting, Clippy, tests, licences and advisories with cargo-deny, the WebAssembly build) and starts the desktop shell under a virtual display; the release workflow builds Tauri bundles for Linux, Windows and macOS, split Android APKs and a web archive, and checks installer sizes; a Pages workflow builds the landing page, manual and web app together.
- The landing page, README banner, social preview and app icons are neutral placeholders until the brand kit is imported.
- The interface no longer loads the Inter and JetBrains Mono web fonts; the brand kit's fonts replace them.

- Kiln Write no longer runs away on table rows taller than a page (WP-63 fix round 1): a row that may not split, a repeated header row or a row of exact height that is taller than an empty page used to move to a new page again and again, producing over a thousand blank pages from a 1 KB file and dropping the rest of the table. Such a row now splits where the page is empty (as Word does), an exact-height row is clipped at the page bottom, and every row of the table is placed. `kiln-cli render` now writes every page of long Word documents (it stopped after 49 of the 300-page test document because Kiln Write lays out later pages lazily).
