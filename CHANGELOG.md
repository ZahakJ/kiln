# Changelog

All notable changes to Kiln (called Officina at first) are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The fidelity corpus and side-by-side scores.
  - 150 real-world files, 50 per format, from the test data of Apache POI and LibreOffice: `fixtures/corpus-manifest.json` holds each URL, SHA-256 and licence, and `tools/fetch-corpus.sh --verify` checks them. 44 more generated feature files cover Arabic and CJK documents, floating tables, columns with footnotes, legal numbering, nested fields, VML fallbacks, form fields, multi-field pivots, slicers, a formula matrix, every conditional format rule type, every transition and animation preset, and 4:3 decks.
  - `cargo xtask fidelity --differential` scores LibreOffice's round trips with the same comparison and writes the side-by-side section of `docs/qa/fidelity.md`; page counts are compared with LibreOffice's over the whole corpus.
  - Each file's reader and writer run in a process of their own with time and memory limits, so a crash or a hang costs that file and not the run. LibreOffice runs with one profile per job, and every process it starts is killed with it on a time-out.
  - The report holds no machine paths, says what is compared, and counts real-world and generated files.
- `.docx` keeps ruby, tracked moves, legacy form field settings, editing permission ranges and alignment tabs on an unedited round trip; markers between table rows and cells stay where they are.
- `.pptx` keeps run-level and paragraph-end text shadows, outlines, underline fills and the symbol font, also where the model merges the runs.
- A workbook's stored results stay until something they depend on changes, also for a function Kiln cannot evaluate; `fullCalcOnLoad` is honoured. An unedited save writes back what the file held.
- `fidelity`: `values` compares what the two files store, `raw_elements` compares their raw XML, for LibreOffice's round trips too, LibreOffice's round trips run with its default settings, a dropped part counts as a loss unless OPC forbids it, and the report carries a digest of its inputs that `site --check` verifies. A run over less than the corpus says so and leaves the report alone.
- The landing site and the manual.
  - The landing page in the brand kit's design: the banner, a real desktop and phone window, Kiln Write, Kiln Grid and Kiln Deck in light and dark with sample documents, Feels like home, Measured not claimed, the comparison table, downloads and a recording. Lighthouse 99 to 100 on all four categories, on the local Pages emulation (`e2e/perf/lighthouse-site.mjs`).
  - `cargo xtask site [--check]`: `docs/data/*.json`, the numbers and the comparison on the page and the manual's function list, from the reports and data files; `docs/qa/compare-facts.json` holds the cited facts and `docs/qa/compare.json` will add measurements.
  - `e2e/specs/docs-media.spec.ts` takes every screenshot and `demo.gif`; `pnpm media:render --screenshots` makes the WebP sizes. The site's fonts are subset WOFF2.
  - The manual viewer in the brand's design, with a page filter, previous and next, and screenshots that follow the colour scheme; new pages: welcome, getting started, Linux, Windows and macOS, file formats, questions, troubleshooting, the keyboard shortcuts (from the keymaps) and the function list (from the formula documentation).
  - The site offers what has been built and run: the browser and a Linux build from source, with the other platforms' cards hidden until they ship. The banner has no platform line. Each comparison cell cites the page that says it, and every number says what it measures.
  - The screenshots and the recording come from the built Pages artefact, not the development server.
  - `tools/check-links.py` checks every internal link and anchor; `tools/pages-build.sh` runs it with `cargo xtask site --check`, and `tools/pages-check.mjs` checks the page's pictures and the manual. The artefact no longer carries the engineering notes at the top of `docs/`.
- The installable web app on GitHub Pages (`docs/manual/web.md`, `e2e/specs/pwa.spec.ts`).
  - `tools/pages-build.sh` builds the site: the landing page and the manual from `docs/`, and the web app under `/kiln/app/` (`vite build --mode pages`); `tools/pages-check.mjs` checks it (chrome JS 389 KB gzipped of 450 KB, every core under 4,500 KB, an installable manifest). `pages.yml` builds it with the script and deploys it.
  - A service worker (`apps/web/src/sw.ts`): the page shell is cached by content-hashed version, the cores, fonts and dictionaries when used and then all of them (but the CJK and emoji fonts, saved when used) a little after the first screen, so every app opens offline.   - Kiln Grid's threads core: `cargo xtask wasm` builds `grid-threads` (atomics, a shared memory, `-Z build-std`), and the Grid Worker runs it on a pool of up to four Workers when the page is isolated (recalculation of 500,000 formulas 811 → 331 ms), falling back to the single-threaded core otherwise.
  - Kiln's own notices: "Kiln has been updated" with Reload (unsaved changes come back in Document Recovery; with "Keep recovery info" off Reload asks about each document first), the install card, Offline and Back online, "Kiln works offline now", and a file Kiln opens only on the desktop.

The CJK font's slices and Noto Emoji are saved when a document first needs them, and are no part of an install or of the first visit's download.
  - A tab left open across a deployment says "Kiln has been updated" with Reload instead of failing, and a window whose core did not start says what to do next, never the error.
  - With "Keep recovery info" off, the browser asks before a tab with unsaved changes closes.
  - A file launched into the running installed app opens in its window, which stays as it was (`focus-existing`); a share does the same in a window with unsaved work. Grid falls back to its single module when its pool of Workers cannot start.
  - The manifest: the brand kit's icons and theme colours, screenshots, shortcuts for a new document, workbook and presentation, file handlers for every format the web cores open (opened through `launchQueue`, saved back to the file) and a share target.
  - The editors and the slide show load as chunks of their own when a window first shows them (the first script of the page: 779 → 389 KB gzipped); `apps/web/src/styles.ts` keeps the stylesheet order of the single bundle.
  - Lighthouse 13.5.0 on the local Pages emulation (`e2e/perf/lighthouse.mjs`): time to interactive 1.4 s on 4G.

- Storage (`docs/manual/files.md`, `crates/kiln-storage`, `e2e/specs/storage.spec.ts`).
  - Native files `.kwrite`, `.kgrid` and `.kdeck` in File ▸ Save As and File ▸ Open: a zip with a versioned manifest, the model, the version history (Write and Deck), the original Office file and which of its parts the edits touched (saved as Office again, it writes what an ordinary save would: the touched parts from the model and every other part, macros and custom XML included, byte for byte); a file from a newer Kiln is refused with the version it needs. `kiln-cli convert` converts to and from them; every docx, xlsx and pptx feature fixture comes back with the same text.
  - The autosave journal: from the first change a document's recovery copy is a checkpoint and the changes after it, written as they happen (Kiln Grid's a second after the last change), with a new checkpoint every 200 changes written beside the old one and switched to last, so a crash at any moment leaves a whole copy; saving marks it saved and closing a document without unsaved changes removes it. Natively it is one file per value in the app's data folder, each write flushed to the disk before the next, shared by every Kiln process (a document one process has open is never taken by another); in the browser in the site's private file system.
  - Document Recovery: after a crash, a closed tab or a reload, a pane on the left lists the documents left unsaved; Open (marked as not saved), Save As and Delete. A copy cut short by the crash keeps every change before the cut; one from a newer Kiln says so and can be deleted; a document open in another tab is not listed.
  - AutoSave to file: the title bar's chip turns it on; the file is written two seconds after the last edit. It stays off for a document without a file, a read-only one, or one whose format would lose something Save warns about (macros, other sheets of a CSV), and turns itself off with a message if an edit makes it so. It never writes over a change another program (or another tab) made to the file: it pauses and asks; one window at a time has AutoSave on for a file.
  - Closing a document with unsaved changes asks Save, Don't Save or Cancel; with AutoSave on the changes are written first.

The gzipped core is 4,634 KB with the charts (B12's interim allowance is 4,650 KB); embedding the fonts would have taken it to about 9 MB.
- Kiln Deck hardening (`kiln-deck`). Presentations and edits refuse positions, sizes and child spaces outside the DrawingML coordinate range, oversized tables (Insert ▸ Table is 1–75 × 1–75) and sections that do not partition the slides, so a file or edit can never leave a deck that cannot be reopened; nudges, scaling, alignment, distribution and timelines saturate instead of overflowing. Theme colour contrast is now measured on the correct 0–255 scale, and the bundled themes were retuned so every placeholder on every layout and variant meets WCAG AA (Jade, Celadon, Cobalt Teal, Terracotta Umber, Kiln Night, Raku Bone, Slate Daylight); accent-filled title and section slides pick light or dark text from their background in each variant.

- Saving a workbook whose formula is nested tens of thousands of parentheses deep no longer exhausts memory and kills the app: the step that adds Excel's `_xlfn.` and `_xlpm.` prefixes kept a copy of the open-parenthesis stack for every token, so a 200 KB formula needed tens of gigabytes; it now runs in linear time and memory (100,000 levels save in a fraction of a second). A part the XML writer cannot serialise is reported as an error instead of being saved empty. CSV and JSON imports follow Excel's limits with one warning each — cells cut to 32,767 characters, rows wider than 16,384 columns and JSON objects with more than 16,384 keys cut to fit (such JSON used to fail outright) — the scalars of a mixed JSON array are kept in a `value` column instead of being dropped, and JSON export writes whole numbers as integers. The 14 formula results LibreOffice cannot vouch for are checked against hand-computed values, and the three workbooks exceljs cannot read against openpyxl.
- Word documents with tables nested thousands of levels deep (Apache POI's `deep-table-cell.docx`, 15,005 elements) now open instead of being refused, and save without losing a word: the XML layer can keep content past its 2,000-element tree limit as verbatim markup (`ParseOptions::keep_too_deep_as_raw`, `XmlNode::Raw`), which the Word reader opts into; tables too deep to follow are kept whole (previously the innermost followed cell's content was dropped from a save); cells ending with a nested table get Word's end-of-cell paragraph on open, so a save and reopen gives the same document, and are saved ending with the table again while that paragraph is untouched, so LibreOffice shows the saved file as it shows the original (all 5,000 levels, visual score 1.00); whether a table is deep enough to keep whole is measured from its content, so content controls or links nested in the deepest followed cell are no longer dropped. `kiln-cli convert` counts relationships parts and the content types among the parts, so its summary never reports more written parts than the package has.
- Statistical distributions are accurate at any parameter size. The incomplete gamma and beta functions behind them used to stop silently after 10,000 terms, so large shapes, degrees of freedom or trial counts gave wrong or impossible probabilities: `GAMMA.DIST(1E8,1E8,1,TRUE)` was 0.3414 (now 0.5000133), `BINOM.DIST(5E14,1E15,0.5,TRUE)` −81.38 (now 0.50000001), `T.DIST(0.5,1E15,TRUE)` 1.443 (now 0.6914625) and `GAMMA.INV(0.5,1E7,1)` 10000001 (now 9999999.67). Large shapes now use Temme's uniform asymptotic expansions, the beta continued fraction keeps its digits next to 1, the prefactors cancel their huge terms exactly, and a method that does not converge gives `#NUM!` instead of a partial sum; cumulative results stay within [0, 1]. `ERF`, `ERFC` and the normal distribution are now accurate to about 1e-15 (the `statrs` versions were off by up to 1e-10), and the large-parameter densities (`GAMMA.DIST`, `POISSON.DIST`, `BINOM.DIST`, `NEGBINOM.DIST`, `HYPGEOM.DIST`, `T.DIST`, `F.DIST`, `BETA.DIST` with `FALSE`) no longer lose digits to cancellation. 30 new conformance rows check large parameters against 50-digit references, and the fuzz test now requires every cumulative distribution function to return a probability. `MMULT` is about 7× faster (1000×1000 by 1000×1000 in 0.4 s) and `UNIQUE` of a million numbers about 14× faster (0.7 s); `functions --list | head` no longer panics on the closed pipe. Correction to the two entries under Added: the suite now has 5,450 rows and 890 documented examples, and the library adds 587 KB gzip to the WebAssembly engine core (the first entry's 4,879 rows, 866 examples and 577 KB were the figures before the thirteen added functions).
- Inverse distributions are exact in the tails and at small shapes, and `BINOM.INV` always finishes. `BINOM.INV` and `CRITBINOM` with 10¹⁶ or more trials never returned and froze recalculation (above 2⁵³ the bisection's `mid + 1` equals `mid`); they now answer in microseconds up to the largest double. The quantile search behind `GAMMA.INV`, `BETA.INV`, `T.INV`, `T.INV.2T`, `TINV`, `F.INV`, `F.INV.RT`, `CHISQ.INV`, `CHISQ.INV.RT` and `CONFIDENCE.T` bisected values for 300 steps, so it could not get below about 10⁻⁹¹ or converge on wide brackets: `GAMMA.INV(0.1,0.01,1)` was 2.45e-91 (now 5.66e-101), `T.INV(1E-18,1)` −1.34e154 (now −3.18e17) and `T.INV(1E-16,2)` −67108864 (now −70710678.1). It now bisects the bit patterns of doubles, reaching adjacent doubles in at most 64 steps at any scale, searches on the smaller tail (and the beta quantile on the side of ½ it lies on), and gives `#NUM!` when the quantile is beyond the largest double. Gamma, beta and F tails at a tiny fraction of the mean (`CHISQ.DIST(2.8E-6,30,TRUE)` was off in the 9th digit, `F.DIST(5.5E-17,1,1000,TRUE)` was 0 instead of 5.9e-9), `T.DIST` beyond ±10¹⁵⁴, `GAMMA.DIST(1E308,1E-300,1,TRUE)` and `NORM.S.INV` of a subnormal probability (both `#NUM!` before) are fixed too, and `BINOM.DIST.RANGE` and cumulative `HYPGEOM.DIST` no longer hang on whole numbers above 2⁵³ either. Cumulative `HYPGEOM.DIST` now sums from `s` away from the mode and stops at the first negligible term, so `HYPGEOM.DIST(1E7,2E7,2.5E7,5E7,TRUE)` takes 10 ms instead of giving `#NUM!`, samples just under the old limit drop from about 1.2 s to milliseconds, and results match 40-digit references to 1e-13. 47 new conformance rows check tail and small-shape quantiles against 60-digit references and the large-count cases, and two new fuzz tests require every inverse distribution to round-trip (the CDF of the quantile returns p) and `BINOM.INV` to finish at any trial count; the cumulative-distribution fuzz test now also fails on any call slower than 5 s.
- `cargo xtask budgets` no longer fails at random on a busy machine: the benchmarks take enough timed runs for p95 to mean something (20 to 200 instead of 3 to 60); a benchmark over a limit is measured again, up to twice, after waiting for other processes to leave half of the CPUs idle, so a row fails only when every attempt misses it; and each attempt records the share of the CPUs other processes used, so when every attempt missed on a busy machine the row is reported as inconclusive rather than as a regression (a quiet machine, such as CI, gives the verdict). `docs/qa/perf.md` shows the attempts and the other processes' CPU share of each benchmark. `kiln-cli` exits 2 when run without a command, ends quietly when its output pipe is closed (`kiln-cli inspect … | head`) instead of panicking, and its control channel rejects arguments and viewport fields it does not know instead of ignoring them. `kiln-cli repack` and the fidelity baseline report `[Content_Types].xml` separately (compared by its declared content types) rather than counting it as a byte-identical part, and `sheet-1m.xlsx` now carries a `<dimension>` on each sheet, as Excel writes.

- Test corpus: 58 generated Word, Excel and PowerPoint feature files plus hand-made edge cases, a script that downloads 30 real-world files, and checks against LibreOffice, ExcelJS, mammoth and the Python Office libraries, with a round-trip fidelity scorer.
- Scriba document model (`@officina/doc-model`): documents keep Word's own structure and units (sections, paragraph and character formatting, tables with merged cells, headers and footers, footnotes, fields, bookmarks, equations, images and shapes, comments and tracked changes), so nothing is rounded or lost when a .docx is opened and saved.
- Styles behave like Word's: Normal, Heading 1–6, Title, Subtitle, Quote, List Paragraph, Caption, TOC 1–3, Header/Footer, Hyperlink, Strong, Emphasis and Table Grid with the Word 2016+ defaults (Calibri 11 pt, 1.08 lines, 8 pt after), and formatting is inherited in Word's order — table style, paragraph style, list level, character style, direct formatting — including Word's rule that Emphasis inside an italic paragraph shows upright.
- Lists number exactly as Word numbers them: multilevel and legal numbering, restart and continue, start values, bullets from Symbol and Wingdings fonts, Roman, letter, ordinal, word and East Asian formats.
- Field codes (PAGE, NUMPAGES, DATE/TIME with date pictures, TOC, REF, PAGEREF, HYPERLINK, SEQ) are understood, and unknown fields are kept unchanged.
- Office fonts are replaced by bundled look-alikes with identical spacing where one exists (Calibri → Carlito, Cambria → Caladea, Arial/Times New Roman/Courier New → Liberation), and fonts that may shift the layout (such as Aptos) are reported.
- Word count statistics as in Word (words, characters with and without spaces, paragraphs; East Asian characters counted one per word), and editing commands for styles, bold/italic toggling that respects styles, font size steps, case changes, lists and indents, tables (insert, rows, columns, merge, split), page and section breaks and page setup.
- Word document reader (`@officina/io-docx`): opens .docx, .docm, .dotx and .dotm files with their text, character and paragraph formatting, styles, lists, tables (merged cells, nested tables, widths in any unit), sections with first-page and odd/even headers and footers, footnotes and endnotes, comments with replies and resolved state, tracked changes (insertions, deletions, moves, formatting changes), fields with their last results (tables of contents become a contents block), hyperlinks, bookmarks, pictures, shapes and text boxes, equations, content controls, right-to-left text and document properties.
- Symbol-font characters (Wingdings, Symbol, Webdings) are shown as their Unicode equivalents and saved back as the original symbols.
- Anything the reader cannot edit yet (charts, SmartArt, embedded objects, legacy drawings, unknown parts) is kept for saving, and the Compatibility Checker gets a list of what will look different, with its location in the file.
- Formula engine (`@officina/formula`): Excel formula syntax including structured table references, 3-D and whole-column references, array constants, `@` and the `#` spill operator; formulas keep their own spacing when rows, columns or sheets change.
- Fast, incremental recalculation: only what changed is recalculated (a 100,000-cell chain in about 0.2 s), with circular reference detection and optional iterative calculation.
- Dynamic arrays that spill into neighbouring cells, with `#SPILL!` when something is in the way, plus LET, LAMBDA (including named and recursive lambdas), MAP, REDUCE, SCAN, BYROW, BYCOL and MAKEARRAY.
- A core set of 47 native functions (SUM, IF, XLOOKUP, FILTER, SORT, UNIQUE, SEQUENCE, TEXTJOIN, INDIRECT…) with Excel-compatible text-to-number, date and comparison rules, and a step-by-step evaluation tree for the upcoming Formula Lab.
- 484 Excel functions across financial, logical, text, date and time, lookup, math, statistical, engineering, information, database, web and compatibility families — including SUMIFS/COUNTIFS/AVERAGEIFS/MAXIFS/MINIFS with Excel criteria and wildcards, XLOOKUP/XMATCH match modes, SUBTOTAL and AGGREGATE that skip hidden and filtered rows, TEXT with Excel number formats, DATEDIF, NETWORKDAYS.INTL, the bond and depreciation functions, statistical distributions, Bessel and complex-number functions, CONVERT, TEXTSPLIT/TEXTBEFORE/TEXTAFTER, REGEX functions, CELL, INFO, ENCODEURL and HYPERLINK.
- Every function has built-in documentation (summary, syntax, arguments, worked examples) for formula autocomplete, the Insert Function dialog and the Formula Lab.
- A formula conformance suite of about 4,600 cases from Microsoft's documented examples and LibreOffice-recorded results; the places where Officina differs from Excel are listed in `docs/formula-deviations.md`.
- Tabula workbook model (`@officina/sheet-model`): sheets with Excel's full 1,048,576 × 16,384 grid in a compact sparse cell store (a million cells fill in about 0.15 s and iterate in under 20 ms), row heights and column widths in Excel's own units (the default column is 64 px), hidden rows and columns, outline levels, merged cells, defined names at workbook and sheet scope, tables, conditional formatting rules of every Office type, data validation, hyperlinks, notes and threaded comments, freeze panes and sheet views, print settings, AutoFilter state and chart/picture anchors.
- Cell formats are stored like Excel's styles.xml — fonts, fills, borders on every side in every style, alignment, protection and number formats — and identical formats are shared, so formatting a range twice never grows the file.
- Every spreadsheet edit is undoable: typing, formatting, inserting and deleting rows or columns (merges, names, conditional formats, validation, tables and every formula follow, with `#REF!` where a reference is deleted, and undo brings the original back exactly), cut and paste, paste special (values, formulas, formats, transpose, skip blanks), sort (several keys, custom lists, left to right), merge, sheet insert/delete/rename/move, freeze panes and more; edits group into one undo step and the history can be saved and replayed.
- Formulas in the workbook calculate as you type through the formula engine, only recalculating what changed, with spilling dynamic arrays, structured table references (renaming a table or a column header rewrites the formulas that use it, and converting a table to a range turns them into A1 references), defined names, manual calculation mode (F9, Shift+F9 for one sheet), the 1904 date system and a step-by-step explanation of any cell's formula.
- Numbers display exactly as Excel shows them: the General format's 11-character rule with automatic scientific notation, rounding half away from zero, dates and times (including elapsed `[h]:mm`), percentages, fractions, scientific, accounting layouts with the currency symbol pinned left, `[Red]`/`[Color n]` colours, conditional sections and localised separators and month names.
- Workbook snapshots as plain JSON (gzip-compressed for storage) for version history, crash journals and background workers.
