# @kiln/protocol

The typed bridge between the presentation layer and the Rust core (PLAN.md §3.5, `docs/adr/0005-bridge.md`).

- `src/generated/` — every protocol type, `catalog.json` (command metadata) and `schema.json` (the postcard schema), generated by `cargo xtask protocol` from `crates/kiln-protocol`. Never edit by hand; CI fails when they are stale.
- `KilnClient` — the one interface the UI uses: `ping`, `execute`, `query`, `open`, `new`, `setViewport`, `frame`, `a11y`, `subscribe`, `hostReply`, `dispose`. Errors are `KilnError` with a stable `kind`.
- `WasmWorkerClient` — the core in a Web Worker (`apps/web/src/worker.ts` uses `serveRequest`), buffers transferred.
- `TauriClient` (lazy, `createTauriClient()`) — `invoke` of the `kiln_*` commands, events over an IPC `Channel`, raw postcard frames; `TauriHost` answers dialogs with the Tauri plugins.
- `WebHost` — answers host requests in browsers (File System Access API, `<input type=file>` fallback, Origin Private File System, `localStorage` prefs, async clipboard, http/https/mailto links only).
- `decode`/`decodeAs` — the schema-driven postcard decoder, tested in Vitest against every vector in `crates/kiln-protocol/tests/vectors`.

Thin by contract (PLAN.md §3.7): this package transports and decodes; it never computes document state.
